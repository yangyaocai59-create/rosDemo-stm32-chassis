# 0.18.25 转向保护调整与开源对照

2026-10-23，Asia/Singapore。用户要求优先处理保护反复中断，参考代表性开源项目。本版为未烧录的候选：修改了转向故障资格判定，**不是只加日志，也不是已经证明先前误报**。延长单轮欠速容忍会使实际堵转/编码器失联被允许更久，必须与保持原保护的0.18.24区分。

## 本工程具体问题与本次范围

0.18.24统一转向有两条竞争的停机路径：故障管理器严重欠速750ms，以及PI内近零反馈1.5秒sticky失败。任一路满足就锁存整车。现有原始CNT确有近零窗口，不能称这些全是误报；但短暂欠速恢复机会少，且PI自身报告可绕过中央策略，让一个参数调整无法完整解释停车时间。

0.18.25把**统一转向模式**资格收敛到故障管理器内单一状态机。NORMAL/滚动转弯和显式关闭统一宏的legacy参考路径保留旧判据。PI内仅保留近零持续时间诊断，不再生成第二个1.5秒sticky停机报告；FF/P/I、PWM300‰上限、斜率、原始计数/USB/IMU都没有调整。

## 候选状态机

- 每轮独立状态，四轮双向同一判据。进入转向/方向改变后宽限1000ms；同向目标刷新不会重置资格时间。
- 达到宽限后，欠速持续250ms出现suspect告警，不关输出、不清积分。
- 若欠速状态持续至2000ms，仍锁存原wheel-stall故障并全车停车，禁止自行恢复；需明确清除后再接收新命令。
- 恢复门槛高于进入门槛，并保持100ms才解除suspect。短速度尖峰或一个计数不能无限重置保护。恢复到门槛之间的速度仍在资格中。
- 输入为速度，告警不阻止PI正常运行；无额外踢力、目标抬高或虚构计数。输出低于某PWM时也不能无限豁免反馈失联。

对目标幅值T≥20cps：

`low=max(min(20,0.25*T),0.15*T)`，同向速度≤low进入欠速；
`recover=max(low+1,0.25*T)`，同向速度≥recover持续100ms恢复。

在约240cps时约为36/60cps，在160cps时24/40cps。补齐旧160目标、21反馈的资格缺口。小于20cps不由此状态机判断，不能说覆盖所有低速。

运行中持续失联从进入low到停机约2秒，调度量化另计；从一开始就无反馈，含1秒启动宽限约3秒停机。**这比旧策略允许更长的无反馈驱动**。2秒是受现有短间歇数据与有限停机需求约束的待验证策略值，并不是已证明电机能安全堵转2/3秒；没有电流与温度采样，不应扩展为无限制长期运行承诺。

急停、STOP、断链、250ms命令过期、任务失联、控制时序和现有超速保护仍按原路径停车，不等这个2秒。车体正在转动不作为单轮保护的无条件豁免；未校准IMU不参与本次安全门控。

## 验证与尚未验证的事

- 纯状态机严格/O2/静态分析各5组：四轮双向、20/80/160/240/280cps、计时回绕、告警/有限停机、100～1800ms可恢复欠速、速度尖峰/滞回区、模式/换向复位、同向命令更新不重置、160目标21反馈有限停机。
- 真实runtime/控制器/故障管理器严格/O2/静态分析各3组：1200ms可恢复欠速不锁存；持续零反馈约3秒停车；旧750ms与1.5秒路径不绕过新pivot策略；NORMAL旧1000+750ms不变。
- 其他现有STOP/断链/ESTOP/精确250ms/任务/时序/超速及交错回归通过，普通模式40000次输出差分一致，USB20组、trace和协议/里程计测试通过。
- 完整Debug清理构建零警告零错误，HEX/BIN/地址/向量检查通过。RAM101472字节（77.42%），Flash190648字节；安全调用链编译器应用帧小计256字节，不能替代实机栈/调度最坏界限。
- 旧0.18.21～0.18.24镜像未覆盖。尚未烧录、开串口、清板上故障或运动，没有新的实车性能结论。

历史采集在原故障点后已经STOP，后续速度为停机结果。不能把它接在新策略后当作仍持续驱动的真实反馈，更不能仅凭离线延后触发就说180°可以完成。本版不承诺修好了真实停顿、编码器输入或角度误差；如果出现持续2秒异常，仍应停车定位而非再无限放宽。
