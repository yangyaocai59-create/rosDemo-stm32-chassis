# 0.20.2 四轮控制候选：反馈时钟竞态修复

2026-10-25。继承 0.20.1 的控制算法，只修复反馈时钟比较和诊断快照一致性。**后续更新：用户烧录 0.20.2 后，六项短时上板复测通过，运行反馈年龄日志为 2–20 ms，未再出现回绕。详见[0.20.2 上板记录](stm32_evidence/2026-10-25-v0202-hardware/README.md)。** 下文保留交付时的实现说明与先前 0.20.1 硬件记录；发布包中离线交付状态未改写。旧版源码备份、固件镜像和发布包全部保留，带载性能及角度精度仍待验收。

## 发现与修复

0.20.1 实测中，UART `CTRL V2 age` 曾出现 `4294967280`、`4294967277`，同期 TRACE2 同步快照中的反馈年龄始终为 1 ms。telemetryTask 在打印前保存循环入口时间，打印多行串口日志后才读取控制快照；期间 motorTask 可以提交更新的反馈，旧时间减新时间的无符号结果发生回绕。

0.20.2 在同一短临界区复制运行统计和控制状态，并在复制后读取当前时间。打印用这个时间计算年龄，避免旧时间戳以及两次复制之间的运动代次不一致。空闲时打印的是最后一次有效控制反馈的年龄，仍会正常增长。

源码复核还发现 `ChassisController_SafetyProcess(now_ms)` 有同类风险：调用方读取时间后若被 motorTask 抢占，随后直接用无符号年龄判断，会把刚提交的反馈误判为过期。此次硬件测试没有触发这一故障；这是由日志线索发现并在主机上复现的缺陷。

新安全判断复用已有的模 32 位有符号截止时间比较：反馈时间 + 41 ms 才到期。40 ms 仍允许，41 ms 停机，真实计数回绕仍正确；调用时间略早于新快照时不会误停。前提与已有命令截止时间一致：相邻有效时间距离小于半个 uint32 周期。反馈输入本身的未来时间戳、重复序列、失效快照检查仍保留。

`test_runtime_v2.c` 新增普通时间/回绕下的落后 1 ms、20 ms 安全调用测试，继续运行 40/41 ms 与未来输入拒绝测试。使用 `TEST_STALE_SAFETY_CLOCK` 可将同一回归施加到旧 201 配置；本机旧配置在“仍应运行”断言处失败，202 通过。记录在 `build/tests/v0202_clock_reproducer`。
