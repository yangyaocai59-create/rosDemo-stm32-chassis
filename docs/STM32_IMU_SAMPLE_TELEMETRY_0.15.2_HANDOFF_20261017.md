# 0.15.2：IMU 新样本驱动遥测与静止残差说明

版本：`0.15.2-imu-sample-telemetry`。基线：`0.15.1-safety-stack`。

这是软件候选版，由用户自行烧录；**尚未在板上验证这版遥测连续性，也没有证明静止漂移变小**。不自动烧录、复位、校准或运行电机。完整构建结果、镜像范围和 SHA256 见包内 `release_status.json` 与验证日志。工程无 Git 仓库，没有可报告的提交号。

## 已确认的问题与证据边界

0.15.1 断电重启后的只读采集位于：

`build/hardware_tests/cold_restore_0.15.1_20261017_060512_265678/`

- Flash 恢复的偏置为 `[-52,19,146]`，采集时 `bias=1`，没有重新校准。
- 3010 个 RAW 帧中有 2999 个独立样本；出现 `10321 → 10323`、时间间隔 20 ms。
- 同一窗口的采集质量 missed/race/timeout 增量为零；USB CRC/RX overflow/TX drop 为零。这些计数不能据此证明传感器绝对无漏采，但不支持直接把该跳样归因于 SPI 读错。

原实现把“采集后更新最新快照”与“独立定时器每 10 ms 发送最新快照”分开调度，两者没有锁相。即使源样本连续，9/10/11 ms 的时间戳变化也能使发送端先重复旧样本，再跳过一个新样本。

新增原生测试使用实际协议和 transport 代码模拟独立时钟：修改前收到 81 帧，其中 3 次重复、3 个源样本被跳过；修改后 SI、RAW、毫秒回绕测试全部连续。这证明**存在该软件机制**，不是对历史板上每一处跳样原因的唯一性证明。

## 修改设计

生产代码仅改三处：

1. `Application/Communication/chassis_usb_protocol.c`
2. `Application/Communication/chassis_usb_protocol.h`（注释说明名义 10 ms 周期）
3. `Application/System/firmware_info.h`

USB 任务每轮检查一个一致快照。有新的 `sample_count/time/epoch` 就发布，不再等待独立的 10 ms 重发时钟。只有成功加入发送队列，才推进发布游标和设备帧序号；背压时仍会重试。

没有新样本时：

- 有效位、传感器状态、读错计数或校准状态变化，立即通报。
- 状态也没变化时每 100 ms 通报一次健康快照，不伪装成 100 Hz 新采集。
- 显式 GET_STATUS 和成功接受校准的即时回复仍允许重复同一源样本；切换 RAW/SI、重开会话后会立即给当前快照。

因此上位机必须按源样本序号/时间戳去重，不能把每个到达的帧都当作一次新测量。ACK 使用主机序号，不应纳入设备遥测序号连续性检查。

仍是 latest-only 快照，**不是无损 FIFO**。若任务长期不能运行或主机堵塞，仍可能跳过采集；没有插值、伪造计数、补零或补发过期运动命令。若板上复测仍有缺样，再根据完整收包、任务与采集计数判断是否需要有界样本队列，不把 FIFO 或 DMA 当成本轮必要修改。

STOP、250 ms 命令超时、SOF/DTR 断链停车、急停、故障锁存均保留。没有改 `.ioc`、任何生成代码、任务栈/优先级、PWM、编码器、SPI 采样率、量程/DLPF、Flash 记录或偏置算法。USB 消息号、字段、长度、单位、默认 SI/可选 RAW v1 均不变，ROS 解码器无需更改。

## 静止漂移：本轮没有做什么

新增离线工具 `Tools/imu_raw_drift_report.py`，只读取保存的 JSONL，不打开串口、不写 Flash。按 RAW 实际灵敏度计算，排除重复样本，显示源间隔缺口、偏置、温度和 10 s 窗口；偏置变化、读错变化、复位/乱序等不能混成一段估计。缺口处梯形积分只是估算，报告不会标成严格连续。

上述历史 0.15.1 窗口：29.988 s、约 27.2℃，Z 轴时间加权残差约 **−0.00740°/s，即 −0.444°/min**，积分约 −0.222°。这是实际保存样本的短时残差，不是新固件实测，更不是 ROS 融合偏航。

还发现一个需要单独处理的精度限制：`ImuStaticTest` 当前用整数除法把 500 个 RAW 均值截断成整数，Flash 与 RAW v1 也保存/报告整数偏置。当前 65.5 LSB/(°/s) 下，1 RAW 对应约 0.916°/min；截断引入的偏差幅度可接近这个量。**不能只凭本次 −0.444°/min 就认定它完全由截断造成**，校准窗口噪声、上电重复性与温度也会造成残差。

本轮不偷偷改成小数偏置：否则 Flash 兼容性、RAW v1 基线含义及 ROS 的 RAW/SI 一致性都必须一起设计。后续若要进一步降低残差，优先讨论带版本的小数偏置表示和较长静置验证；不能靠强制静止归零掩盖慢速真实旋转。没有增加开机自动校准、在线偏置学习或未经标定的温补。

## 软件验证与烧录后验收

- 实际 Debug clean build，Error/Warning、FLASH/RAM 以包内记录为准。
- 14 个原生程序（包含新增独立时钟、健康通报、背压重试、计数回绕）；13 个 Python 测试；协议 self-test。
- 旧 STOP/GET_STATUS 50 次、真实 SOF 超时、DTR/deconfigure 停车离线回归保留。这不是实板运动安全认证。
- 包装检查与 0.15.1 冻结源码相比，除上述三处生产文件外的代码及硬件配置字节不变。旧交付包不覆盖。

用户若决定烧录本候选版：

1. 关闭电机 VM，自行全片擦除并烧录包内 `firmware/rosDemo.hex`；无需改 CubeMX。全片擦除会清掉当前偏置。
2. 先读取启动版本，静态检查 SI/RAW 源序号、时间间隔、CRC/队列计数、任务周期与栈余量。查询回复造成的重复要与周期遥测区分。
3. 静态检查后另行授权一次校准；保持固定静止，确认保存成功。
4. 完全断电再上电，只读检查偏置恢复；保持相近温度采集至少 2 分钟，再比较连续性与 RAW 漂移。不要只看整数 `wz=0` 就说没有漂移。
5. 只有完成新的硬件验收后，再另行确认 VM/架空或安全场地，进行原定电机启停对照。本轮不发送运动指令。

离线复核历史残差示例：

```powershell
python Tools\imu_raw_drift_report.py build\hardware_tests\cold_restore_0.15.1_20261017_060512_265678\raw_samples.jsonl
```

输入可以是每行一个 20 字段 RAW 数组，或 `{"raw":[...]}`。原始证据不改写；指定 `--output` 时只允许新建派生 JSON 文件。
