# 0.18.19：LR反向运行恢复与安全衔接候选

日期：2026-10-22，Asia/Singapore。版本：`0.18.19-lr-running-recovery`。用户批准将已通过离线检查的v2原型合入并编译，由用户手动烧录。**这是软件候选，不是稳定发布；交付时未烧录、未做新实车验证。** 本轮未打开串口、运行车辆、清实板故障或校准，也没有提交/推送Git。

## 1. 改什么、不改什么

依据.18[单次落地左转](stm32_evidence/2026-10-22-v01818-ground-left/README.md)中LR连续160ms零计数，以及[条件性离线分析](stm32_evidence/2026-10-22-v01818-lr-rf-review/README.md)，合入[LR运行恢复v2](stm32_evidence/2026-10-22-lr-running-prototype-v2/README.md)。v1曾导致自动堵转计时退化，已拒绝且历史证据保留；**本版不是那个被拒绝的v1加旧安全代码**。

相对冻结0.18.18，六个生产文件变化：

- `Application/Chassis/chassis_controller.c`：仅LR反向PIVOT，旧支撑为零且已确认同向运动后，将运行恢复移交PI；退出/停止清理。
- `wheel_speed_controller.c/.h`：LR运行补力/I协调、有限episode、状态清理及内部只读安全查询。公共状态结构与USB帧布局未变。
- `wheel_speed_control_config.h`：新增LR研究参数；旧PWM/I/斜率上限不变。
- `Application/Safety/fault_manager.c`：完整旧堵转条件保留，另加LR所有权限定的持续严重欠速保护，消费现有故障锁存及四轮关断。
- `Application/System/firmware_info.h`：版本更新。

另修改运动测试入口、两处LR旧策略波形断言的适用条件，新增八个测试/辅助文件。未改其他轮控制策略、首次起步、普通直行/滚动转向、编码器采样/滤波、PWM引脚/频率、USB/Jetson协议/会话、IMU算法/Flash、CubeMX、RTOS任务配置或几何。**不暗中抬高ROS转向速度，不提高PWM上限。**

## 2. LR运行规则

1. 只有LR反向PIVOT、同向速度≥50 cps累计40ms，且旧起步active已退出、旧applied/steady bias均为零，才移交新策略。旧支撑尚未退出时继续旧策略，不叠加新补偿；不能宣称覆盖所有LR历史。
2. 运行欠速超过`max(20 cps,目标×10%)`或接近静止，连续60ms后开始一次渐进补力。较原来等低通速度很低才补力更早，但不是立即追加完整60‰。
3. 临时项爬升≤250‰/s，与已有同向I共享原60‰预算；原I±50‰、PWM±300‰、输出斜率1000‰/s保留。协调阶段抑制重复正误差积分。
4. 已确认同向运动且未超速，可按≤40‰/s把临时项转给I，保持总和，不是额外再加一份。首次超速/反向运动停止增力，临时项按400‰/s撤减。
5. 一次episode在600ms停止增力并有限退场；静止不重复尝试，恢复到目标附近100ms且临时项归零后才允许下一次。模式/方向/低目标/Reset及既有停车路径清理状态。

以上计时由有效控制dt离散处理，不是独立硬件定时器。真实效果取决于负载、供电、轮胎/地面及电机；同一规定反馈的回放不能预测实车改善。

## 3. 安全衔接及覆盖边界

旧条件表达式和1000ms宽限、750ms连续检测、目标≥200 cps、反馈低于目标15%的数值保留。新增条件仅用于已获得新策略所有权、目标反向且与最近PI目标一致的LR：**持续严重欠速时不再要求当前PWM≥100‰**，避免补力撤减重置750ms计时。与完整旧条件取OR，不以新策略替换旧保护。

这是更严格的保护，可能比旧PWM门控更早终止无力的动作。故障仍为`WHEEL_STALL`、LR mask `0x02`；runtime健康故障关断四轮、拒绝新运动。反馈恢复、控制器Reset不能自清故障；显式清除本身不能恢复旧命令。

**低于200 cps的LR独立失败覆盖没有扩展**，未取得所有权的首次起步/残留旧支撑历史仍走旧策略，不能把750ms宣称为所有工况的物理停车保证。原STOP/零速/真实断链/250ms命令超时/ESTOP/健康故障/控制时序及超速保护不等待补力结束。

## 4. 正式离线验收与已知测试限制

- 当前运动入口62组、USB入口20组通过；包括保留的原47组（LR旧波形断言明确限定适用范围）及新增15组。原冻结.18完整runtime 15组另行保持通过；没有删除历史测试来伪装全兼容。
- 新LR策略确认、共享权限、有限退场、3万步对抗输入、八类runtime停车出口、故障边界/锁存/显式清除及回绕检查通过。实际代码/模拟外设，不是实车试验。
- 204组自动失速审计：I从−50到+50每1‰及额外+6.7，各含普通/回绕时基。新候选均在规定零反馈开始后760ms关断（20ms采样下的750ms名义检测），没有晚于旧策略/旧保护。v1曾有1.64～2.36s的退化。
- 8万次未改范围、1万次首次起步与冻结.18逐行一致；3万次当前LR运行控制及私有状态与验证过的v2原型一致。原LF首次起步隔离120010次继续通过。
- 19个IMU/RAW Python测试及本地协议self-test通过。原IMU校准/存储/采样等11组主机断言执行通过。

**扩展IMU整套严格脚本未通过，不写成全部回归通过。** 其关闭校准/探针配置下，未改的`imu_service.c`中`ImuService_AbsI32`变成未使用函数，`-Werror`因此报错。源码及相关驱动/配置哈希与.18一致，与本次LR修改无关；正常固件配置使用该函数，clean构建没有此警告。

保留原始失败日志。为补充功能检查，仅在两个独立主机构建中将`unused-function`从error降为warning，同时要求唯一警告必须是这个函数，其他警告/错误仍失败；随后polling 4组、probe 3组执行通过。这不等于修好了原严格脚本。**没有为此修改IMU源码、算法或其原测试入口。**

## 7. 用户手动烧录后

1. 关闭电机VM，再按既定**全片擦除**流程手动烧录本候选。全擦会丢失IMU保存偏置，本版不改变这一事实，也不自动校准。
2. 烧录后先保持VM关闭，只读确认启动版本、无故障、计数、USB及IMU状态；按需单独确认静止条件后重新校准IMU。
3. 经现场安全确认，再做架空左右检查，关注LR/前轮连续性、PWM/速度和任务栈高水位。落地测试需另行确认，不因本次编译授权就自动运行。
4. 仅在通过前置检查后做单次落地对照，观察LR是否还停住后突然加速、其他轮是否退化；故障立即结束，不自动清故障重试，不放宽保护。

本版还没有新实车数据，不能承诺已消除LR短停、全部四轮波动或ROS转向误差。
