# 0.18.9 后轮再启动时序候选

日期：2026-10-20（Asia/Tokyo）。版本：`0.18.9-rear-restart-timing`。

状态更新：用户已烧录，完成左右各 6 秒地面对照，反馈“更连续、更均匀”。末段 LR 零计数消失、右转总体误差下降，但 RR 左转仍出现约 720 ms 连续零计数和 495 cps 峰值，不能标记通过。详见 [0.18.9 实板证据](stm32_evidence/2026-10-20-v0189-powered-pivot/README.md)。下文保留设计与构建交付记录；离线回归不能代替实车验收。

## 实测依据

[0.18.8 地面证据](stm32_evidence/2026-10-20-v0188-powered-pivot/README.md)显示：RR 两方向平均/RMS 和峰值改善，但左转末段连续零计数约 620 ms，前轮及总体误差退化。用户感觉“更平稳、速度更均匀”，并不等于控制通过。

RR 左转在源时间 69282 ms 再启动时，已有约 44.8‰ 积分支撑，先补 15.2‰。后续记录显示 300 ms 等待后才加码，并按 100 ms 周期恢复；到 STOP 前 PWM 达 187‰，原始计数仍为零。该窗口在补偿完全恢复至原上限前结束，不能证明轮子必须超过原上限才能转起。

本次只缩短后轮“再次启动”的恢复等待，同时让检测到运动后的补偿尽早交回 PI。没有继续加大最大 PWM，也没有统一加大 KP。

## 与 0.18.8 的差异

| 条件或参数 | 0.18.8 | 0.18.9 |
| --- | ---: | ---: |
| 后轮再启动首次分级增加等待 | 300 ms | 80 ms |
| 仍接近静止时的后续增加周期 | 100 ms | 40 ms |
| 每次增加幅度 / 上限 | 10‰ / 60‰ | 不变 |
| 后轮再启动最短保持 | 300 ms | 40 ms |
| 交回 PI 的目标方向滤波速度门槛 | ≥50 cps | 不变 |
| 前轮或当前方向首次起步保持 | 300 ms | 不变 |

只在该轮已于当前 pivot/方向观察到运动后，才进入后轮再启动分支。入口锁存该标志：不能因为首次起步过程中刚观察到运动，就把第一次启动误切成短保持模式。

其余规则继续沿用：

- 后轮再启动先按已有同方向积分补差额；保留残余 bias，不突然撤小。
- 仅当目标方向滤波速度不超过 20 cps 时才增加补偿。20..50 cps 中间区间不继续加码，也不提前交接。
- 每次实际执行最多加一级；延迟执行不循环追赶，下一期限从当前执行时刻计算。
- 检测到至少 50 cps 且保持达到 40 ms 后，后轮再启动结束，采用既有 FF/I 平顺交接；它不是直接撤掉启动力。
- 同向超速 P、积分、PWM 限幅及斜率均不变。交接瞬间 FF+I 保持连续，此后由 PI 误差调节卸载；不能保证轮子一动，实际 PWM 就立即下降。

以 0.18.8 那次初始补 15.2‰ 为例，如果反馈持续近零且任务准时执行，新版约在 80/120/160/200/240 ms 增至 25.2/35.2/45.2/55.2/60‰；旧版对应为 300/400/500/600/700 ms。该计算只是调度与限幅，不是物理转动保证。40 ms 的交接最短保持对应实测 20 ms 控制周期的两个周期；80 ms 为四个周期。

加码更早可能重新增加超速，提前交接也可能不足以维持带载转动。因此必须同时观察再启动后的峰值、连续零计数时长以及其他轮子的跟踪，不能只看平均速度或现场听感。

## 范围和保护

相对 0.18.8，生产代码仅涉及：

- `Application/Chassis/chassis_controller.c`：逐轮后轮再启动入口锁存、差异化保持时间、限频恢复分支。
- `Application/Chassis/wheel_speed_control_config.h`：40/80/40 ms 时序常量与注释。
- `Application/System/firmware_info.h`：版本。

测试、README 和本文同步更新。没有修改 PI 数值、编码器计数/极性、滤波、PWM 外设、IMU、USB 布局、任务周期或 ROS 几何参数。

保持不变：首次起步/前轮补偿 60‰、积分 ±50‰、总 PWM ±300‰、斜率 1000‰/s、基础 KP=0.05、pivot 同向超速 KP=0.15、KI=0.25。STOP、故障、250 ms 指令超时和断链停车不经过本次补偿时序，继续立即禁用输出；离开 pivot、换向及停车清理相应状态。
