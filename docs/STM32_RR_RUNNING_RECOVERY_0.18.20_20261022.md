# 0.18.20：RR 正转运行中恢复候选

日期：2026-10-22，Asia/Singapore。版本：`0.18.20-rr-running-recovery`。

用户批准将[离线 RR 原型](stm32_evidence/2026-10-22-rr-running-prototype-v1/README.md)集成并完整编译。**这是软件候选，不是稳定发布；交付时尚未烧录、尚未实车验证。** 本轮未连接串口、运行车辆、清实板故障、复位或校准，未创建提交或推送。

## 1. 本次改动范围

只给 **PIVOT 模式、RR 正目标、确认已经转动且旧启动补偿退出后的运行中恢复** 加入协调。当前轴向下主要对应左转时右后轮正向转动，不是提高所有前进指令的速度或动力。

相对冻结 0.18.19，六个生产文件变化：

- `Application/Chassis/chassis_controller.c`：RR 限定交接、停止/退出清理。
- `wheel_speed_controller.c/.h`：独立 RR 运行状态、渐进补力/I 共享预算、只读安全查询。
- `wheel_speed_control_config.h`：仅新增 RR_RUN 设置，全部旧宏定义保持不变。
- `Application/Safety/fault_manager.c`：完整旧条件与 LR 条件均保留，额外 OR 一个 RR 所有权限定低速保护。
- `Application/System/firmware_info.h`：候选版本号。

控制及安全算法与通过验证的 RR 原型除注释/空白外一致。未改编码器采样、极性、滤波、PWM 引脚/频率/上限、USB/Jetson 协议或会话、IMU 算法/Flash、CubeMX、任务配置、几何或 ROS 参数。RR 反转、NORMAL/直行、其他轮的控制策略及首次起转旧策略保留。

另更新五个已有测试/入口文件，新增九个 RR 测试/辅助文件。原 .19 版本及测试冻结在离线证据中，旧四个烧录归档文件保持不变。

## 2. 控制规则

1. 同向速度 >=50 cps 连续 40 ms，旧 startup pulse 已退出且 applied/steady bias 都为零，才能交给 RR 运行策略。若旧补偿仍非零，继续旧策略，不强行接管或叠加补力。
2. 明显欠速连续 60 ms 后渐进补力；误差带 max(20 cps, 目标的 10%)，近静止阈值 min(20 cps, 目标的 25%)。
3. 临时补力 A 与同向积分共享原 60‰ 权限：max(0,I)+A <=60‰，浮点检查容差 0.001‰。I 仍 ±50‰，PWM 仍 ±300‰，输出斜率仍 1000‰/s。
4. A 上升 <=250‰/s。确认同向运动且未超速时，A 可按 <=40‰/s 转入 I，转移保持 A+I，不叠加同帧正误差积分。
5. 第一个超速样本即结束增力，A 按 400‰/s 撤减；反向运动也结束增力。原超速 P/I 处理仍在。
6. 一次 episode 到 600 ms 的首个更新退出增力并有限衰减；静止不会无限重试。连续稳定恢复 100 ms 且 A=0 后才可准备下一次。方向/模式/低目标/Reset 清状态。

上述按有效控制 dt 离散处理，不是独立硬件计时器。STOP、零速命令、断链、急停、健康故障、250 ms 超时、控制周期异常和超速故障均立即沿原四轮关断路径执行，不等待渐变结束。

## 3. 堵转保护与边界

原 legacy 堵转条件和原 LR 所有权条件完整保留，参数不变：启动宽限 1000 ms、连续资格 750 ms、目标 >=200 cps、同向速度低于目标 15%；legacy 的 PWM >=100‰ 门槛仍适用于原路径。

额外 RR 路径仅限 RR 正转运行策略已有所有权、观察目标与最新 PI 目标一致的情况；其持续严重欠速资格不再依赖 PWM >=100‰，避免临时补力撤掉后重新开始 750 ms 计时。使用原轮故障计时器、WHEEL_STALL、RR mask `0x08`、健康故障锁存及四轮关断。

这是收紧保护，不是放宽保护，可能更早终止严重欠速的动作。反馈恢复、控制器 Reset 不自动清除故障；模拟显式清故障也不能自动恢复旧命令，仍需新命令。所有权查询只读，使用原 fault-manager 临界区；它不是所有控制字段的原子时间戳快照。

**目标低于 200 cps 的后轮独立失效覆盖未扩展。** 未取得新所有权的旧启动/残留补偿历史仍走旧策略；不能把 750 ms 宣称为所有工况的物理停机保证。

## 4. 正式离线验收

- 正式运动入口 **79 组 PASS**，USB 入口 **20 组 PASS**。
- RR 新增 17 组：5 组策略、8 种立即关断路径、4 组故障边界、2 组交接检查、冻结 .19 完整 runtime、隔离、原型一致性和故障网格。
- RR：80,000 次非改动范围 +10,000 次首次起转更新与 .19 逐字节一致（含 LR 私有状态）；30,000 次 RR 已交接运行输出/状态与离线原型一致。
- LR：30,000 次已交接运行输出/状态与原 LR v2 原型一致；80,000 次旧范围对照明确排除本次有意改变的 RR 正向 PIVOT，改由上述 .19 对照覆盖。LR 首次起转 10,000 次仍一致。
- LR 与 RR 各 **204 组**实际 runtime/fault-manager 模拟审计，包含 I=-50..50 每个整数及额外历史种子、正常/回绕时基；全部在规定持续无反馈后 760 ms 关断，无新增延迟；锁存、四轮关闭、拒绝命令、模拟显式清除/无自动恢复均通过。这是 20 ms 观察步长下的 750 ms 名义检测，不是实车响应测量。
- 原冻结 .18/.19 完整 runtime 各 15 组仍通过。当前 runtime 只对原来两处已有 LR 排除加上 owned-RR 条件：不再用旧“立即 restart 波形”要求新策略；其余断言保留，新行为独立测试。
- LF 首次起步隔离、前轮补偿/失效联动、原普通轮速和电机驱动检查保留。
- IMU/RAW Python **19 个测试**、协议 self-test 通过；原 IMU 校准/存储/采样已执行 **11 组**主机断言通过。

**既有扩展 IMU 测试限制仍在，不能称全部严格测试通过。** 在关闭校准/探针主机配置下，未改的 `ImuService_AbsI32` 因未使用被 -Werror 拒绝。原始失败日志保留；仅在两个独立补充主机构建中将 unused-function 从 error 降为 warning，并要求唯一警告就是此函数，随后 polling 4 组、probe 3 组通过。未修改 IMU 或原严格测试入口。正常固件配置的完整构建无此警告。

前置历史反馈回放中，原型提前 140 ms 渐进补力、同一反馈下峰值 PWM 170→166‰；这是规定输入的输出对照，**不是实车速度、停顿次数或转角改善证明**。新的实车结果尚不存在。

## 7. 用户手动烧录后的顺序

1. **关闭电机 VM**，由用户按既定全片擦除流程烧录本 HEX；不需要修改 CubeMX 或接线。
2. 全片擦除会丢失 IMU 偏置，本版不改变该事实，也不自动校准。
3. 烧录后先保持 VM 关闭，确认版本、无故障、USB/IMU/计数状态。IMU 校准需单独确认车体静止条件后执行。
4. 再经现场安全确认做架空左右检查，重点看 RR 及其他轮有无停住后突然加速，检查任务栈高水位。
5. 架空正常后，另行确认落地空间和线缆，再做最小范围落地对照。故障立即结束，不自动清故障重试，不放宽保护。

不能承诺已消除 RR 计数缺口、整车波动或 ROS 转向误差；这些必须由后续实车数据验证。

## 8. 后续实板结果：性能未通过

用户报告已烧录，并要求直接做落地检查。供电开启后只读无故障，执行[单次落地左转300](stm32_evidence/2026-10-22-v01820-ground-left/README.md)，完成6秒并确认停车、端口关闭；用户明确观察“RR有明显停顿后恢复或突然加速”。末段RR可见至少140ms零增量且起点截断，USB同净计数跨度240ms；LF/RF另有300/180ms缺口。补偿输出阶跃减小但实际性能未通过，不作为稳定发布或整车验收通过。

没有触发故障、清故障、校准、追加运动或再次烧录；固件与产物未改。交付时的软件验证结果仍为历史记录，不将其覆写为实车通过。后续先离线分析恢复/滤波时序及四轮联动，不直接提高PWM或放宽保护。
