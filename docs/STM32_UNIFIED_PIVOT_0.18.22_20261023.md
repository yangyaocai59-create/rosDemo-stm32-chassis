# 0.18.22：四轮统一连续 PI 转向候选固件

日期：2026-10-23。状态：**软件验证候选，不是实车验收通过版本**。

后续独立审查更新：**暂缓烧录**。前馈/I余量及中段诊断仍有未闭环项，不能按本文原交付顺序直接进入试车。详见[用户五项问题复核](stm32_evidence/2026-10-23-v01822-user-review/README.md)；镜像和受审查生产源码未改。

## 本次做了什么

不再继续叠加 LF 首次起步、RF 负载恢复、LR/RR 运行恢复等分支。正式默认的原地转向路径改为四个独立实例、同一个单轮控制公式：

`车体目标 → 原有速度规划/运动学 → 四轮各自 FF + P + I → PWM限幅/变化率限制 → 原有驱动`

每轮保存自己的积分、上次输出和方向；使用原有各轮独立测速输入。四轮参数可以不同，但控制算法相同。同向目标更新不会重置积分；不会每收一包才点动一次。停止、换向和退出转向模式清理相应状态。

这一版**没有额外的起步脉冲或停顿恢复补力**。先让正常速度闭环独立工作；之后只有实测证明必要，才讨论统一、有界且仅起步介入的规则。不把旧有复杂补偿换个名字继续运行。

普通直行/滚动转弯的速度控制公式不变；对四轮 PI 状态更新增加了与任务级 STOP 串行化的短临界区。启动仍在原有 runtime 启动事务内完成，输出提交保留停车代次检查。临界区内不增加串口等待或日志。

## 前馈与 PI 的准确含义

现有基础前馈来自旧的架空扫描，原 VM 记录还存在未核实假设；前轮转向偏置也是旧的暂用值。**本次没有取得新的带载标定，不能声称已经实现“带载标定完成”。**

候选转向中 `FF = 方向对应的静态项 + 增益×|目标cps| + 固定转向偏置`，整体取目标方向符号。转向偏置在 0～160 cps 按目标幅值渐增，到 160 cps 后固定，不因运行阶段/欠速/超速另开状态机。

在 ±240 cps 时，暂用 FF 幅值如下，单位为千分比，不是百分比：

| 轮子 | 正向 FF | 反向 FF |
| --- | ---: | ---: |
| LF | 146.840 | 146.525 |
| LR | 80.842 | 85.601 |
| RF | 149.987 | 135.998 |
| RR | 96.770 | 93.159 |

四轮初始 `Kp=0.050 ‰/cps`、`Ki=0.250 ‰/(cps·s)`，每轮配置独立。方向归一化后每个有效控制周期计算 `I += Ki×误差×dt`；仅在积分会继续推入输出/变化率饱和时阻止该次积分。没有欠速冻结积分、阶段到期撤补偿或超速三倍 P 切换。积分可为负，允许撤减过大的前馈。

保留 PWM 上限 ±300‰、积分 ±50‰、输出变化率 1000‰/s、轮速目标上限 ±1600 cps。20ms 周期正常输出最多变化约20‰，但安全停机可立即覆盖为零。实际电机能否在这些旧参数和上限下克服地面负载，仍需测试；若不足，先做统一的带载前馈拟合，而不是单轮临时加补丁。

## 安全边界

没有提高 PWM 上限，没有扩大上位机小速度命令，没有关闭急停、250ms 命令超时、USB/SOF/DTR 断链停车、任务健康或 IWDG。故障仍锁存、停止四轮；清故障不恢复旧命令。

为避免移除旧补偿后保护随 PWM/补偿阶段消失，统一转向所有权纳入严重欠速保护：保持原有 ≥200cps、低于目标15%、启动宽限1000ms、持续750ms 条件，不再依赖新 PI 的 PWM 是否恰好跨旧门槛。完整旧保护条件仍保留。

原前轮连续近静止1500ms保护现在统一适用于四轮转向实例（目标至少20cps；反馈幅值不大于 `min(20cps, 目标25%)`）。这是**覆盖范围的保守扩展，不是放宽或延后保护**，不能说所有保护判据完全未变。失败报告保持到复位，由 fault manager 关断；普通直行不进入此路径。本版没有合入另一个“原始计数短时容忍度”离线原型，不能宣称已消除所有反馈停机。

内部保留历史命名的 `GetFrontPivotState` 安全查询接口：统一路径下可返回任一活动转向轮的近静止报告，临时补偿字段恒为0；不是新增的USB报文，也不表示仍有旧前轮恢复脉冲。

## 计数、协议与 IMU

编码器、测速估计器、定时器引脚/滤波配置、运动学、几何尺寸、USB 帧结构/单位/顺序、RAW v2、IMU 和 Flash 偏置持久化源码均未改；与封存 .21 源码逐文件核对。控制器只改变驱动力，不修补、缩放、替换或补造原始编码器计数。

原始计数真实也不代表四轮滑移转向的里程计角度天然无误差。ROS 有效轮距仍需用地面外部角度基准校核；本次不修改 ROS 的395mm有效轮距，也不把目标角度或 IMU 角度伪装成编码器角度。

## 参考了什么、没有照搬什么

[Linorobot2 固件](https://github.com/linorobot/linorobot2_hardware/blob/jazzy/firmware/src/firmware.ino)用20ms定时控制分配四轮目标、读取各轮反馈并调用四个独立PID实例；参考的是周期控制与状态隔离，不是其车辆参数。

[Leo Rover 底盘层](https://github.com/fictionlab/diff_drive_lib/blob/1.5/src/diff_drive_controller.cpp)负责目标分配与输入超时；[单轮层](https://github.com/fictionlab/diff_drive_lib/blob/1.5/src/wheel_controller.cpp)负责反馈、PID与PWM变化限制。参考这种职责边界；没有复制其编码器跳变剔除/计数偏移修正，因为本项目要求原始计数独立上报。

[ROS2 diff_drive_controller 官方说明](https://control.ros.org/jazzy/doc/ros2_controllers/diff_drive_controller/doc/userdoc.html)的轮关节速度接口不能替代底层电机速度闭环。这里不改它的接口，也不把开源项目的结构当成本车性能已验证的证明。候选算法为本项目独立实现，没有拷贝这些项目的控制源码。
