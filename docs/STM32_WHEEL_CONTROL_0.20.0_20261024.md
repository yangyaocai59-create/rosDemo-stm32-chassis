**0.20.0 四轮控制优化候选 — 2026-10-24**

本版基于0.19.1，属于独立版本，状态为离线验证候选。没有连接串口、清故障、校准、烧录或运行车辆；没有完成实车性能、热安全或导航精度验收。用户已授权直接实施软件优化，因而本轮完成可离线验证的控制、诊断和构建工作，无中途询问。

**版本隔离和回退依据**

- 工作分支：`codex/four-wheel-v0200`；原分支和原提交保留。
- 修改前备份：`build/backups/v0191-before-v0200/source.zip`，同时有源文件/旧发布文件SHA256清单。396个源文件和174个已有归档文件纳入校验。备份脚本重复执行只检查，不更新已有基线。
- 新构建配置：`WheelV0200Debug`、`WheelV0200Release`，分别输出到 `build/WheelV0200Debug`、`build/WheelV0200Release`。
- 新镜像名称：`rosDemo-0.20.0.elf/.hex/.bin`；归档目录 `build/firmware/0.20.0/Debug`、`Release`。
- 新交付包：`releases/0.20.0/rosDemo-0.20.0-offline-candidate.zip`。包内含镜像、MAP、完整源码ZIP、源码清单、构建和主机回归日志、验证JSON。
- 包装脚本拒绝覆盖已有0.20.0归档；以后修改应使用新版本目录。不会重建或覆盖原 `build/Debug`、`build/Release` 或原发布目录。
- 原Debug/Release配置的默认控制修订仍为191。新版配置显式设置 `CHASSIS_CONTROL_REVISION=200`，启动日志显示 `0.20.0-wheel-control-candidate`。主机历史回归使用191，不将其旧行为通过算作新版性能证明。

**实现的控制变化**

1. 新版四轮共用 `wheel_control_core.h` 中的纯计算 FF+PI 核心，保持四个独立状态和按轮/方向的标定表；固件中不编译旧两条控制路径。旧实现仍可用修订191重建和比较。
2. 普通行驶与原地转向切换使用实际已施加输出跟踪积分，不直接清积分。积分能力不足的残余仍受输出斜率限制，因此不声称所有情况下数学上完全无扰。
3. 原地转向仍按线速度≤1mm/s、角速度≥0.010rad/s进入；已进入后，在3mm/s和0.005rad/s退出边界内保持模式，减少阈值附近抖动。
4. NORMAL保留双向输出能力，PIVOT保留沿目标方向驱动/撤力的策略；没有擅自把两者的制动语义强制改成相同。零速、正反转换和驱动换向互锁均保留。
5. 抗饱和同时考虑幅值和输出斜率；驱动实际输出不同于请求时，回写实际输出历史并保留积分、目标和方向状态。下一周期不会按未实现的输出继续爬升。
6. 每周期先取得控制器事务副本，在临界区外计算四轮候选；提交前核对运动代次、命令代次、事务修订及急停。Stop、Reset或新命令能使旧结果失效。
7. 修复Runtime整形期间新速度命令取代旧命令时可能进入控制失败路径的问题；新版将其视为正常替换，下一周期处理最新意图。
8. 将现有静态前馈模型反算为方向/工况对应的目标上限。当某轮基础前馈已经超出300‰时，左右目标共同按比例缩小，保留分配曲率。这个边界只代表已有前馈模型，不是带载实测能力保证，P/I仍可能饱和。
9. 混合线/角运动共享轮级加速度预算，避免两轴独立上限在同一轮相加。预算取现有单轴轮级限制的较大值，纯直行和纯原地转向的既有加减速斜坡保持。

**反馈、安全与诊断变化**

- 编码器累计计数、四轮顺序、PPR/倍率和硬件TIM配置保持。估计器增加统一序号和质量位，拒绝超过100ms的估计间隔及超过20000cps的明显计数异常；异常时保留原始累计位置，不合成计数。
- 控制器要求四轮同一时刻、同一序号、同一采样间隔，且反馈有效/有限。样本年龄最多40ms，序号必须向前推进；安全任务也独立检查40ms年龄，超限撤销驱动并报告反馈故障。该时限比原先仅检查valid更严格。
- 原PIVOT的1000ms宽限、250ms预警、2000ms持续欠速、100ms恢复确认保留。新版将持续反馈保护覆盖到所有模式和≥1cps目标，模式切换不清其历史；普通≥200cps的原750ms路径仍作为更早保护。
- 低目标恢复门槛不再高于目标本身。测试覆盖1cps及真实低通/200ms归零规则下每秒一个计数的稀疏反馈；这不是所有地面低速可控性的实车证明。
- 新增独立的整段运动统计：每轮误差平方和/绝对值和、峰值误差/积分、PWM/斜率/执行器限制次数、非零目标下原始净增量为零的样本数和最长持续窗口。统计覆盖成功启用至最后一次成功提交，停车后保留到下一次成功启动。
- “净增量为零”只描述采样计数，可能包含正常低速量化或往返抵消，不能独立证明物理停转。
- 新增DWT周期统计，分别记录电机/安全循环和采集、控制、trace段耗时。计时包含抢占，并非纯函数CPU时间；尚未实板测量，不能据主机测试声明WCET达标。
- PWM比例的64位换算移到PRIMASK关中断区外，GPIO/CCR提交和急停复核仍受保护。没有改变2ms换向最短保护；实际换向重试仍受20ms控制周期影响。
- trace使用独立生产/消费暂存，减少任务栈占用。TRACE2 schema3继续保留，新版BEGIN声明 `control=1` 并增加 `CONTROL2` 行，导出反馈序号、运动代次、模式、分配比例和限制原因。更新后的解析器验证扩展完整性并拒绝缺行/重复/越界数据。
- 限制位：1=目标分配/目标限幅，2=输出幅值，4=输出斜率，8=模式交接，16=执行器实际输出回写。
- USB消息布局、ACK/STOP语义、单位、原始编码器上报和IMU协议不变。

**保留的参数和实际边界**

轮径65mm、每圈1560counts、有效轮距395mm、20ms采样、50ms低通、200ms无计数归零、PWM上限300‰、积分±50‰、既有FF/PI系数及250ms命令超时保持。

固定前轮补偿60–65‰与积分±50‰之间的余量问题没有用猜参数解决。本版保留最近实车使用的系数，不声称已经完成带载前馈优化。20ms/50ms组合的响应延迟也仍需实测选择；没有直接提高控制频率或启用未经验证的新滤波器。

没有启用电压补偿、加速度前馈、jerk整形、同侧交叉耦合、IMU角速度外环或在线轮距自适应。它们需要独立数据和模型验证，不能因为额度可用就将未标定控制策略堆入主路径。

**离线标定工具**

`Tools/fit_wheel_feedforward.py` 从明确标为稳定且有效的CSV拟合每轮正反方向的电压域kS/kV。要求实际PWM和同步电压，剔除饱和、方向错误、跟踪异常与源故障，检查速度覆盖和残差。结果包括拟合条件、覆盖范围、残差和未完成项；不写固件参数，不自动启用电压补偿。

CSV列：`wheel,target_cps,measured_cps,pwm_permille,supply_mv,steady,valid`；可附 `quality_flags,output_flags,fault`。实际数据中的电压不能用假定12V补齐。示例：

```powershell
python -B Tools/fit_wheel_feedforward.py steady.csv --condition loaded_pivot_floorA --output fitted_floorA.json
```

只接受新的输出文件名，避免覆盖标定证据。合成数据测试验证系数恢复和异常拒绝，不代表本车已标定。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/tests/run_wheel_v0200_tests.ps1
python -B Tools/package_wheel_v0200.py
```

打包脚本自动查找已安装的CMake、Ninja和ARM工具链，执行主机回归、独立Debug/Release clean构建，再校验HEX校验和/地址、BIN一致性、向量、版本字符串、链接符号、内存和保护文件哈希。原固件清单在前后复核。已有归档会拒绝重新打包，应使用新版本。

新版测试包括：100000步混合模式属性检查、四轮双向切换、事务失效/Stop与新命令交错、反馈年龄40/41ms/序号/NaN/回绕、真实Runtime与FaultManager、1..1600cps保护和稀疏计数、60000组混合运动轮级加速度检查、真实测速估计器、驱动换向互锁、trace开关输出一致与扩展损坏拒绝。C测试运行strict、O2、fanalyzer配置。另运行191兼容回归和191/200两种配置的USB回归。

Debug/Release的实际RAM/FLASH和每函数栈帧见 `build/firmware/0.20.0/verification.json`；静态栈帧不等于完整调用链最坏栈，仍须实板检查水位。Debug保留既有调试入口，Release不启用Debug专用故障注入/开环测试宏。

**后续实车工作**

实板验证需先比较原版/新版相同命令的速度、输出、计数与停车时序；再按不同速度、电压及负载标定前馈和PI。现有轮式角度与IMU参考约9–10%的差异仍未得到外部真值确认，不能据本轮软件回归宣布转角或导航精度达标。

设计参考为ROS 2 Humble diff_drive_controller的差速/运动约束、WPILib/SysId的电压域辨识方法及Linorobot2的轮级职责划分；本轮算法为本工程内实现，没有整体移植其他平台固件，也未改动IMU代码。
