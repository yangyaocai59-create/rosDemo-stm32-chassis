**0.20.1 四轮控制优化候选 — 2026-10-24**

这是本轮继续复核后生成的最新候选，继承[0.20.0的控制、反馈、保护、限幅和诊断优化](STM32_WHEEL_CONTROL_0.20.0_20261024.md)，另外加固启动事务。没有烧录、实车运动或校准，软件验证不代表实车性能或导航角度已经验收。

**本次修复**

原生产Runtime用外层临界区保护启动，但底盘公开启动接口也供诊断使用。直接调用时，若Stop在反馈读取/启动准备期间到达，原接口缺少最后一次运动代次检查，可能继续启用输出；即使最终没有启用，旧计算也可能在停车后重新写入PI状态。

新版冷启动和已启用输出接管都先复制事务和停车代次，在私有状态中清零/准备四轮PI，最终只有代次、事务修订、急停和输出条件仍匹配时才提交并启用。Stop使旧启动失效；过期启动的错误处理也不会覆盖停车后的状态。正常接管仍保留原先的输出方向与斜率约束。

公开启动接口自身现在具备这个保护。Runtime原外层启动保护仍保留，因此不声称启动整段已全部移出临界区。主循环四轮PI计算仍采用0.20.0的临界区外事务计算。

同时把新增全模式保护的启动/预警日志改为“Feedback guard”，避免普通行驶保护仍显示“Pivot”造成误读。

**验证和复现**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/tests/run_wheel_v0200_tests.ps1 -ControlRevision 201
python -B Tools/package_wheel_v0200.py --version 0.20.1
```

函数和脚本名称中保留v0200表示此控制系列，共享脚本由参数选择201。新版新增冷启动/输出接管与Stop交错、反馈读取后Stop、失效启动错误处理、成功接管及时间回绕测试；原100000步控制属性、60000组运动整形、反馈/保护/驱动/trace和USB回归继续执行，相关C测试运行strict、O2和fanalyzer。

历史差分所需的7个C/头文件已按原始字节封存到 `Tools/tests/baselines/v01821` 和 `v01825`，并带参考来源及SHA256。它们仅参与主机测试，不进入固件编译；`.gitattributes`避免Git在Windows上转换其换行导致证据不一致。

新版源码ZIP可以独立编译，也可在具有本机GCC、Python及PowerShell的解压目录运行新版/兼容主机回归，不要求携带整个Git历史。脱离原工作区时，没有原固件备份清单的检查会明确输出SKIP；这不构成旧固件已保留的证明。交付包的打包流程仍在原工作区强制执行保留校验。

Debug/Release完整clean构建、HEX/BIN/向量/地址验证、源码/产物哈希、单函数静态栈和内存占用都记录在 `build/firmware/0.20.1/verification.json` 及 `validation/`。静态栈帧不是完整最坏调用链证明，板上水位和DWT耗时仍需后续测量。

**参数与实测边界**

本版没有修改20ms采样、50ms低通、编码器计数、机械几何、300‰ PWM上限、±50‰积分限制或既有FF/PI参数，也没有启用未经标定的电压/加速度补偿、IMU外环或在线轮距调整。

新增反馈年龄40ms、持续反馈保护覆盖≥1cps及高目标前馈包络缩放等行为来自0.20.0，仍需实板验证其运行范围。很低的命令若实际上无法克服死区且持续无计数，会进入保护，不能以自动抬高目标掩盖不可控低速。

带载前馈重标定、滤波/周期选择、有效轮距/外部转角真值以及整车性能验收仍需实际数据。离线标定工具只生成带条件和残差的拟合报告，不自动写入固件参数。
