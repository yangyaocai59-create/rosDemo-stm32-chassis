## 为什么修改

0.18.17 的两次落地左转 0.30 rad/s 都因 LF 恢复失败终止，LF 各只有 3 个计数，第二次用户观察为基本没转或明显停住。旧控制器的恢复在目标斜坡期间提前计时，300 ms 恢复结束前未用足现有补力权限；临时项退出后留下约 15.9% 输出，未正常起转。

[冻结 C 诊断](stm32_evidence/2026-10-21-v01817-lf-start-review/README.md)解释命令形成机制，不确诊唯一物理根因。[离线原型](stm32_evidence/2026-10-21-lf-first-start-prototype-v1/README.md)完成回归后，本版按同一控制逻辑合入。不能据此断言供电、机械负载或驱动一定没有问题。

## 本次独立变更

相对冻结 0.18.17，仅三个生产文件变化：

- `Application/Chassis/wheel_speed_controller.c`：增加 LF 反向首次起步私有历史及有界恢复窗口。
- `Application/Chassis/wheel_speed_control_config.h`：新增 600 ms 总计时、100 ms 全额支撑保持条件，更新解释性注释；原增益/限幅数值未变。
- `Application/System/firmware_info.h`：更新版本身份。

另新增四个主机测试文件并更新运动回归入口。已有其他断言文件未修改；历史 LF/RF 隔离脚本保留，当前入口改用冻结 .17 的首次起步隔离对照，避免拿历史版本“不变”假设评价本次授权变化。

RF、两后轮、LF 正向策略、普通直行/滚动转向、编码器、采样/滤波、PWM 引脚/频率、USB 协议/会话、IMU/Flash 校准、任务/CubeMX、故障管理和几何均未修改。不暗中放大 ROS 指令，不新增最低转向速度。

## LF 新规则

1. 仅 LF 反向、PIVOT 策略目标幅值至少 20 cps、尚未确认运动时的首次近停恢复可延长。底盘原有 PIVOT 选择条件仍为 `|vx|≤1 mm/s、|wz|≥10 mrad/s`。
2. 从该策略阶段进入累计有效控制 dt，目标大小变化不重新计时。特殊恢复在首个累计达到 600 ms 的控制更新退出；这是离散计时截止，不是独立硬件定时器。普通 20 ms 周期下按帧处理，异常但仍有效的较大 dt 有至多一个有效控制周期的量化差；控制更新超过原 100 ms 限制仍走原时序故障关断。
3. 原恢复 300 ms 计时到期后，只有“当前负载项及可用临时支撑预算都已到位并累计 100 ms”才结束特殊恢复；若先到 600 ms 截止、确认运动或发生首次超速，提前退出，不保证所有负载都有 100 ms 全额保持。
4. 若近停确认发生太晚，无法在该特殊窗口容纳原 300 ms，沿用旧 300 ms 分支，不缩短旧恢复。600 ms 是特殊首次延长的截止，不是所有后续恢复的全局计时。
5. 仍静止时只尝试一次，不循环补力；确认运动后的再次停顿沿用旧恢复。模式/方向/低目标/零速/Reset 清理私有状态；RF Reset 不影响 LF。

原 LF 反向负载上限 65‰、I/临时项共享 50‰、PWM 上限 300‰、输出斜率和合成支撑升降预算均保留。运动/超速后仍撤减临时项和支撑，不靠无界积分堆积起转。

**1500 ms 连续近停恢复失败条件及原堵转保护不放宽。** STOP、零速度停止、真实断链、250 ms 命令超时、ESTOP、健康故障、时序/超速故障仍立即关闭输出，不等待补力窗口结束。

## 风险与烧录后顺序

没有提高 PWM 上限，不代表瞬时输出相同：本修改有意提供更长且实际更高的首次支撑。带载可能起转，也可能仍堵转，或挣脱阻力后加速；不能预先承诺流畅。整车转向跟踪、RR 历史积分等既有问题不因此自动解决。

请关闭电机 VM，按用户既定全片擦除流程手动烧录。全擦仍会丢失保存的 IMU 偏置，本版不自动校准，也不改变这一事实。

烧录完成后先只读确认启动版本、状态、供电、计数和 IMU 标志，再经用户确认四轮架空固定、安全条件满足后检查双向连续性。落地测试另行确认；若出现无反馈、故障、突然冲动或异常声音立即结束，不自动清故障重试、不放宽安全保护。
