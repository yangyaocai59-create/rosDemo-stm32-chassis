# IMU 静止漂移统一改造方案（2026-10-16）

状态：架构与接口方案已确定；STM32 0.14.3 接口已实现并通过真实构建/离线回归，用户已刷写，RAW 长采样/模式恢复、显式校准保存和普通断电恢复均实板通过；**ROS 估计器与联调待进行**。当前保存/恢复偏置 [-55,26,150]、seq=1，原 seq=4 属于旧固件诊断。实测见 `STM32_IMU_RAW_HARDWARE_VERIFICATION_20261016.md`。固件接口交付完成不等于零漂目标通过。

## 1. 直接确定的分工

**STM32 负责真实、可追溯的传感器采集与 Flash 基准偏置；ROS 中独立处理模块是唯一的运行时残余零偏补偿方。**

- STM32 不增加开机自动校准、运行时自适应零偏、角速度死区或自动 Flash 写入。
- 保留现有显式五秒校准、校准互锁、A/B Flash 记录和普通上电恢复。每次全片擦除重刷后仍需人工显式校准一次。
- 固件本轮只增加按会话选择的完整精度 RAW 遥测，保留原协议格式与默认行为。
- ROS 先将 RAW 与同快照的 Flash 基准偏置转换为双精度 SI 数据，然后由独立模块估计**仅 Z 轴**的运行时残余偏置，估计结果仅存 RAM。
- ROS 不每次启动调用 STM32 的 0x05 显式校准命令；不得自动保存 Flash。后台静止估计无需用户操作或阻塞系统启动，但它确实会在满足条件时估计运行时偏置，不应宣传成“完全没有在线零偏估计”。
- 不开发 Nav2、SLAM 新功能，不调底盘 PID、轮距、引脚、供电或重启问题。

为什么这样定：三轮实板得到 -4.53、+0.85、-2.63°/min；后两轮基准偏置完全相同。问题是固定偏置不能始终匹配实际零点，而不是 Flash 丢失或 ROS 单位错误。ROS 能联合已发送指令、底盘状态、四轮计数及 IMU 数据进行判定，且便于回放验证和切换传感器；不让低层传感器驱动偷偷改变测量语义。

## 2. STM32 改动范围

预计改动 `Application/Communication/chassis_usb_protocol.[ch]`、主机协议测试/解析工具及必要的版本、文档；若现有测试桩缺字段，仅补测试桩。尽量直接利用 `ImuServiceSnapshot` 已有 RAW、应用偏置、时间戳等字段，不改采集/存储算法。

不改 `.ioc`、CubeMX 生成外设配置、USB transport 链路判定、STOP、250 ms 运动超时、DTR/真实断链停车、故障管理、PWM、编码器及看门狗。

### 2.1 兼容策略

- 协议封装仍为 v1、小端、CRC16，最大 payload 52 B 不变。
- 保留 0x84 IMU_STATE 的 46 B 布局及 mrad/s 等单位，不能偷偷改成更小单位。
- 新命令 `CMD_SET_IMU_STREAM = 0x06`，payload 恰好 1 B：`0=LEGACY`，`1=RAW_V1`。其他长度返回 BAD_LENGTH；其他值返回 BAD_VALUE；ACK 使用原有格式。此 ID 在当前工程未被占用。
- 每次新 USB/DTR 会话默认 LEGACY。旧工具无需修改即可继续使用。新 ROS 驱动每次会话主动选择 RAW_V1，等 ACK OK 并收到有效 0x85 后才认定协商成功。
- RAW_V1 模式用 0x85 **替代本会话的** 0x84，维持 100 Hz，避免两路重复 IMU 流；STATUS、WHEEL、BATTERY 不变。
- DTR 关闭、物理断链或现有会话超时路径复位到 LEGACY；这些路径的原有停车行为不能改变。
- 0x06 只是遥测选择，不是运动指令，不刷新 250 ms 运动指令看门狗，不清故障、不取得运动所有权。可在非正常运动状态查询数据，不应绕过任何现有安全状态。
- 旧固件返回 UNSUPPORTED 时，ROS 可保留旧遥测用于诊断并清楚标记降级；不能把“不支持 RAW”当成电机/安全故障锁存。不得声称旧接口满足本轮高精度验收。重新协商不允许触发自动校准。

### 2.2 新帧 IMU_RAW_V1（0x85，payload 52 B）

| 字节偏移 | 类型 | 字段及含义 |
| --- | --- | --- |
| 0 | uint32 | sample_time_ms，MCU 采样完成时间 |
| 4 | uint32 | sample_count |
| 8、10、12 | int16 各一 | accel_raw X/Y/Z |
| 14、16、18 | int16 各一 | gyro_raw X/Y/Z，尚未减基准偏置 |
| 20、24、28 | int32 各一 | 当前实际应用的基准 gyro_bias_raw X/Y/Z |
| 32 | int32 | temperature_mC |
| 36 | uint32 | read_error_count |
| 40 | uint32 | consecutive_errors |
| 44 | uint16 | gyro_lsb_per_dps_x10，目前为 655，即 65.5 LSB/(°/s) |
| 46 | uint16 | accel_lsb_per_g，目前为 8192 |
| 48 | uint8 | state，沿用现有 IMU 状态枚举 |
| 49 | uint8 | flags，沿用现有 IMU flags，不是 STATUS flags |
| 50 | uint8 | raw_format_version，固定 1 |
| 51 | uint8 | reserved，固定 0 |

Python struct：`<IIhhhhhhiiiiIIHHBBBB`，必须以 `calcsize == 52` 的测试锁定布局。

所有传感器值和基准偏置必须来自**同一次一致性快照**。基准偏置无效时三轴基准字段发 0，flags.bias_valid=0，不得拿未验证值修正。RAW 已是当前固件规定的 body-frame（+X 前、+Y 左、+Z 上），ROS 不能再进行同一次轴交换/反号；ROS frame_id/TF 应如实描述已转换的数据，不趁本轮更改既有坐标关系。

ROS 换算，使用 float64，中间不取整：

```text
Sg = gyro_lsb_per_dps_x10 / 10.0
omega_base[i] = (double(gyro_raw[i]) - double(bias_raw[i])) / Sg * pi / 180
accel[i] = double(accel_raw[i]) / accel_lsb_per_g * 9.80665
omega_corrected.z = omega_base.z - residual_bias_z_rad_s
omega_corrected.x/y = omega_base.x/y
```

先转 double 再减，避免定宽整数溢出。校验 payload、格式版本、reserved、非零比例、state/flags、时间连续性；重复 sample_count 不参加估计。USB 断开、MCU 时间重置、比例或基准偏置变化必须清空残余估计，禁止沿用另一设备/另一基准的估计值。

RAW 不会让传感器本身精度凭空增加，但避免再损失为整数 mrad/s，也允许对整数 RAW 求浮点统计，保留均值的小数部分。

## 3. ROS 处理与输出

驱动只解析、换算和发布基准修正后的 `/imu/data_raw`，保留原时间映射，不添加在线残差补偿。独立组件 `imu_bias_estimator` 发布 `/imu/data_corrected`，只有后者用于正式 EKF 的 IMU 角速度输入。不要同时融合这两路相关数据，也不要在驱动、估计器和 EKF 前处理里重复扣同一个偏置。

`data_raw` 在本文特指“保留设备 Flash 基准修正、未经过 ROS 在线残差修正”，应在驱动说明中写明；真正未减基准的 ADC/RAW 计数通过诊断记录保留。

两路消息均为 sensor_msgs/Imu，角速度 rad/s、加速度 m/s²。无姿态解算，不伪造航向或四元数估计，orientation_covariance[0]=-1。保留重力分量。非零协方差由实测噪声与残余偏置不确定度确定，不能设置为 0 表示“完全可信”。

诊断至少输出：DISABLED/CANDIDATE/TRACKING/FROZEN/INVALID、是否有已接受估计、估计值 rad/s、样本数、窗口均值/方差、温度、拒绝原因、RAW 模式是否协商成功。未获得静止估计时正常发布基准数据并报告“未收敛”，不通过虚构姿态、清零角速度或修改底盘安全状态掩盖它。

输出拆分、SI 单位和缺失姿态表示参考 [ROS 2 Humble Imu 消息定义](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/Imu.msg)；将后续估计留给独立消费者的分层原则参考 [REP-145](https://github.com/ros-infrastructure/rep/blob/master/rep-0145.rst)（该 REP 状态为 Draft/Informational，不把它当成本项目算法效果保证）。

## 4. 残余估计规则：地面机器人模式

以下数值是**第一版可配置起点，不是已验收的传感器指标**。先在记录回放和架空/静止实板验证，通过后再用于落地运动。

### 静止候选必须同时满足

1. 本节点实际发送给 STM32 的运动请求为零，且至少连续 2 s 无任何非零请求；不能只看输入 topic 或 STATUS 被量化为零的速度。
2. 底盘 IDLE、两个 fault 为 NONE、无诊断占用、控制器未激活。STATUS 0x0010 是 SOF 链路存活，**不是电机关闭或静止位**。现有 STATUS 不直接报告 STBY，不得虚构该信息。
3. 四轮的累计编码器计数在候选期及整个估计窗口内均未变化，四轮 cps 均为零。不能只看滤波轮速的四舍五入值。
4. 新鲜有效的 RAW/轮子/STATUS 数据：初始建议 IMU 相邻 MCU 时间间隔 <=30 ms，WHEEL 不旧于 150 ms，STATUS 不旧于 300 ms；接收端还需检测主机超时及会话变化。
5. IMU READY/valid/initialized，无正在进行的显式校准，连续读取错误为零，基准偏置有效。
6. 在随后 5 s、至少 450 个唯一新样本的窗口内：三轴陀螺标准差分别 <=0.0015 rad/s，三轴基准修正后角速度均值绝对值分别 <=0.005 rad/s；加速度各轴标准差 <=0.08 m/s²，模长均值 8.8..10.8 m/s²。必须用未经过本估计器修正的数据判定，避免“已经清零所以认为静止”的循环。

任一条件破坏立即丢弃候选窗口；不跨运动、丢包、校准、会话或复位拼接。阈值需针对实测调整，但不为得到 PASS 无限制放宽。

### 估计与运动时行为

- 首个有效窗口：以 `mean(omega_base.z)` 作为残余偏置（double），不写设备 Flash 或磁盘配置。
- 后续仅在有效静止窗口更新：每 1 s 用最近有效 5 s 均值更新，EWMA 时间常数初设 10 s；残余绝对值上限初设 0.005 rad/s，超过上限只报告异常，不夹紧后当正常。
- 一旦有非零请求、轮子计数变化或不满足静止条件，立即停止学习；已有有效偏置冻结，仅从真实测量中减去这一固定偏置。**运动数据照常保留，不按角速度阈值清零。**
- 数据失效时不发布“新鲜有效的修正样本”。会话/MCU 时间/基准偏置或比例变化时清空估计；短暂窗口被打断只冻结已接受的值。停用估计器时明确输出未在线修正的数据。
- 启动不要求操作人员等待校准、不阻止既有运动链启动。如果一上电立即运动，尚未获得静止窗口时不能承诺已经抑制残差。

### 明确的适用边界

这是“正常落地、外界没有把底盘拿起持续转动”的运行模式。仅靠六轴 IMU 和编码器，不能严格区分某些极慢、匀速的外力整体旋转与残余零偏。不能承诺靠这些门限解决不可观测性。手持、转台、传感器方向验证和特别慢的外力转动测试必须关闭估计器，或额外提供可信静止约束。

持续运动时估计被冻结，温度/零点仍可能变化。此方案不承诺任意时长运动的绝对航向不漂；本次目标只是可验证地改善真实静止下的残差。温度先记录，不用现有三组数据拟合补偿曲线。不借此新增磁力计、姿态融合或 SLAM 改动。

## 5. 实施顺序和验收

1. STM32 侧先实现兼容的 RAW 遥测选择、主机解码、协议/会话/快照一致性测试，执行真实 Debug clean build，报告错误/警告/FLASH/RAM；不自动烧录。
2. 保留现有 seq=4 现场证据，交付新固件、SHA256、源码变更和协议文档。用户按既有“全片擦除”流程刷写后，明确做一次显式校准，不假设旧记录能保留。
3. 固件侧用电脑验证 RAW 100 Hz、同快照 RAW/SI 换算、校准前后基准字段切换、新旧工具兼容、DTR/断链/重连恢复及原 STOP/运动超时保护。不要为了传感器验证自动跑电机。
4. ROS 工程师按本方案实现解析与独立 Z 残余估计器。先离线回放：静止有效、匀速转动、零指令但编码器变化、微振动、IMU/轮子/STATUS 陈旧、复位、重新校准、比例变化都必须覆盖。现已取得 0.14.3 完整 100 Hz 静止 RAW，见实板记录；运动/异常数据与综合回放验收仍待补充。
5. 实板至少三次普通断电上电；每次不重做 STM32 校准，静止收敛后持续记录 >=120 s，同时保留 RAW 和 corrected。每个连续 60 s 窗口由修正角速度积分，目标绝对值 <=1°/min；报告原始残差、收敛耗时、有效窗口数和拒绝原因，不能只展示最后一帧为零。
6. 运动回归必须另行确认场地/架空安全条件；左右转符号和角速度幅值保留、学习立即冻结、STOP 后可继续控制、断链停车和故障互锁不回退。静止测试通过不等于运动回归通过。

未完成双方实现和实测前，不标记“漂移已修复”。后续无需再协商补偿归属；若物理安装/使用工况超出本方案边界，再报告新的约束。
