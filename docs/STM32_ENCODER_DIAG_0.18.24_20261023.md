## 本轮源码复核结论

四轮仍各自从TIM1/LF、TIM2/LR、TIM3/RF、TIM4/RR读取CNT，差分、方向归一后累计；测速基于累计差分，USB读取测速快照中的累计值。没有找到按目标补数、滤波回写累计值、正常运行中清CNT或重新初始化四个定时器的调用。HAL编码器启动仅在初始化路径，失败回滚才停止已启用的通道。

引脚为PE9/PE11、PA15/PA1、PA6/PA7、PD12/PD13；对应AF1/AF1/AF2/AF2。配置TI12、PSC=0、IC1/2直接输入、滤波6、无GPIO上下拉；ARR为65535/4294967295/65535/65535。仅凭配置里的RISING字样不能认定少算四倍频；这里是定时器正交编码模式，须结合实际CNT变化验证。

以上是静态源码与规定寄存器输入测试，不能证明运行时配置一直正确，也不能证明编码器脉冲完整。之前用户观察连续而累计值停住，仍然不能唯一归因于硬件或软件。本版只补齐区分证据，未宣布顿挫或里程计已达标。

## 新增记录

新增 `Application/Diagnostics/encoder_diagnostics.c/.h`，调用位于原motorTask后输出诊断快照内。没有修改`encoder_service.c`、测速、FF/PI、保护判据、USB或IMU。TIM/GPIO读取不调用启停、初始化、写CNT或自动修复；不读可能涉及捕获标志清除序列的SR/CCR输入捕获寄存器。

原TRACE2继续保留，但BEGIN与END的`schema`升级为3；新增每轮：

```text
TRACE2 ENC LF sampled=... live=... bad=... ab=...
```

- `sampled`：EncoderService上一次实际采集保存的原始、未方向归一CNT。
- `live`：诊断读取时硬件TIM的CNT；比sampled稍晚，正常运动时二者允许不同。live不同不能单凭一帧认定采集错误。
- `ab`：GPIO IDR瞬时读数，bit0=通道1/A、bit1=通道2/B。它只是读取时电平，20ms采样有混叠，不能证明这20ms没有跳变或完整统计脉冲。
- `bad`：只读配置检查。0表示当次检查项与本工程设定一致，不代表波形、电源、线缆或电机一定正常。

bad位定义：

| 位值 | 不符合本工程预期的项 |
| ---: | --- |
| 1 | CR1.CEN未开 |
| 2 | SMCR.SMS不是TI12编码模式3 |
| 4 | CCMR1输入选择/分频/滤波不是0x6161 |
| 8 | CCER通道使能/输入极性低8位不是0x11 |
| 16 | ARR与当前计数宽度不符 |
| 32 | PSC非0或CR1.CKD非DIV1 |
| 64 | 两个引脚MODE、AF或PUPDR不符 |
| 128 | 对应TIM或GPIO时钟未开启 |

DIR是正常动态状态，不作为配置错误。此检查是有限集合，未声称覆盖全部TIM/GPIO寄存器或亚周期配置扰动；使用同一配置的内存破坏也不一定被检测。

## 如何据此排查

1. 相邻同一轮`sampled`按16/32位回绕并应用原极性后，应该与累计计数变化相符。若不符，先查采集/发布的一致性；不要补数。
2. 若sampled与累计都停住而live连续跨多个采样推进，说明应重点查采集更新/读取时序；不能只因单帧live领先就判故障。
3. 若两者均停住且bad非0，优先定位对应的运行时使能/复用/滤波等异常。
4. 若两者均停住且bad为0，当前软件资料仍不足以区分真实近停、输入脉冲不到、输入波形异常或净计数抵消。需要独立脉冲/轮动证据；不能承诺仅凭20ms GPIO电平彻底解决。

本版依然冻结第一次异常的128帧；后续故障可能不在同一冻结窗口，必须明确区分。没有把前一个LF窗口当作后一个LR事件的完整证据，也没有无限增大缓冲以保存全程。
