## 同步串口核对

- 前进 STOP：MCU 290289 ms；后退 STOP：293109 ms。
- 两次均记录 `ACTIVE -> IDLE: explicit stop; motors disabled`。
- 两次 STOP 的 USB snapshot：`alive=1 dtr=1 open=1`，`now=last`、age=0。
- 最终 STOP：415099 ms，age=1；关闭 CDC 后 415604 ms 记录 DTR-closed/session ended。关闭发生在已停稳之后，不等于“运动中 DTR 停车”验收。
- 在相同 120 s 静置窗口，左右各 600 条 ENC 串口记录；LF raw=26、LR raw=56、RF raw=44、RR raw=34 均固定，delta=0。右侧归一化 total 为负是当前编码器方向配置的正常表现。
- 本次捕获中无 ERROR 行、无新的 Boot Banner，也无 USB TX 压力诊断行。没有诊断行本身不是零丢帧证明；零丢帧依据是全程 STATUS 的 tx_drop=0。
- 捕获起点已有 LF/LR/RF/RR total=`[0,5,-1,0]`，本轮不清计数；这些在捕获前形成的数值不作为本次静置异常。

## 证据及结论边界

目录内保存 `boot_log.txt`、`events.jsonl`（USB 原始收发字节及解码事件）、`summary.json`、`ch340_raw.bin`、`ch340_chunks.jsonl` 和 `ch340.log`。原始串口与文本日志字节数一致。

同类旧版 0.13.2 双路捕获测试在前进 STOP 附近出现 tx_drop 0→1，提前退出；本次 0.13.3 完成前后短运动及两分钟观察，没有相同丢帧或 0x0140 异常。这是修复有效的实板证据，但不是原始 ROS 脚本端到端验收，也不是历史 LF 静止 +4 根因已解决的证明。
