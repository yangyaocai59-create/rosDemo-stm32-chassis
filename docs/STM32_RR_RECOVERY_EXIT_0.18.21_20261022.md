# 0.18.21：RR 恢复退场与停车代次保护候选

日期：2026-10-22，Asia/Singapore。版本：`0.18.21-rr-recovery-exit`。

实板状态更新：[用户报告烧录后的单次落地左转](stm32_evidence/2026-10-22-v01821-ground-left-once/README.md)完成6秒、120命令均接受、无故障并停车。用户感觉RR连续，尾段RMS改善，但整段USB中仍有140ms RR净计数平台与83→8cps欠速/恢复；详细PWM环恰未覆盖该中段，不能判断唯一原因或宣称解决。不追加运动/新版本。以下构建与“尚未烧录”表述记录的是交付时状态，不替代本次实板结论。

用户批准在[离线原型](stm32_evidence/2026-10-22-rr-exit-prototype-v1/README.md)通过后，复核并发边界、正式集成和编译。**软件候选已生成；尚未烧录或实车验证，不是稳定版。** 本轮未打开 CDC/CH340、运行车辆、清故障、复位、校准、刷写、提交或推送。

## 1. 针对的问题与范围

0.18.20 落地左转时用户确认 RR 停顿后恢复/突然加速；规定反馈回放发现，原始计数已恢复时，滤波速度仍落后，临时补力 A 还在转入 I，保持了较高的总支撑。这是恢复阶段退场时序的优化依据，**不是最初不转的唯一根因**。

本候选仅调整 **RR 正向、PIVOT、已确认运动且旧启动补偿退出后的 running recovery 退场**。不提高目标或 PWM，不将 ROS 小速度命令放大，不改其他轮参数、编码器采样/极性/滤波、USB/Jetson 协议、IMU/Flash、CubeMX、任务优先级/周期、几何或 ROS 参数。

相对冻结 .20，仅五个生产文件变化：

- `Application/Chassis/wheel_speed_controller.c/.h`：RR 计数观察接口、私有退出证据和退出锁存；普通 PI 仍使用原滤波值。
- `Application/Chassis/wheel_speed_control_config.h`：仅新增 RR_EXIT 采样与确认参数，全部旧宏不变。
- `Application/Chassis/chassis_controller.c`：快照只读取本地 RR 增量/周期/时间戳；RR 观察、owner 选择和 PI 更新串行化，增加停车代次校验。
- `Application/System/firmware_info.h`：版本号。

`fault_manager.c/.h` 与 .20 完全相同。另改三个测试入口，新增九个测试/辅助文件；旧测试断言保留。旧 LR/RR 测试入口不再错误要求整个源码等同 .20，改为纯轮策略对照已批准原型，chassis 新差异由专门并发测试覆盖。

## 2. 控制规则

1. RR 采样周期 15..30 ms、年龄不超过一个采样周期，时间戳顺序连续；缺失、重复、倒序、未来、过期、无效周期或异常极值不能复用证据。无有效快证据时退回原滤波策略，不新增故障。
2. 两个同正向、相邻的有效计数样本构成 30..60 ms 窗口，使用实际周期加权。窗口与最新单样本都超过 `target + max(20 cps, 10% target)`，连续确认累计至少 40 ms，才允许快通道退出。标称 20 ms 下通常需三个样本、两个重叠窗口；不是两个统计独立窗口。
3. 原始短窗已接近目标、明显高于滞后滤波值时，暂停继续增长 A 及 A→I 转移；确认超速后按原 400‰/s 有限撤减 A。不是单脉冲直接替代普通 PI，也不是新增反向制动。
4. 退出后再次静止不无限重启 A；稳定再武装沿用旧条件，新计数仍提示超速/加速矛盾时不能提前再武装。改变目标清确认历史，Stop/Reset/退出模式清 RR 历史。
5. 保留 PWM ±300‰、I ±50‰、正向 I 与 A 共享 60‰、输出斜率 1000‰/s、A 增长至多 250‰/s、600 ms episode 和全部旧安全停车机制。

在历史相同输入及条件化初始状态下，原型与正式代码均于 MCU 162782 ms 开始撤减，.20 为 162802 ms；撤完为 162882 与 162902 ms，提前 **20 ms**。同一 162782 ms，RR PWM 由 .20 的 158‰ 变为 150‰。三种打印量化种子一致，其余三轮全部回放导出字段一致；**全段峰值仍同为 169‰**。这些是指定反馈下的控制器输出，不预测实车轮速或停顿缩短。

## 3. 并发复核与保护

轮速快照本身沿用已有临界区一致复制。原型中把新 RR 历史直接写在取快照阶段，可能与安全任务 Stop/Reset 交错，正式版改为：

- `GetSpeeds` 只复制本地 RR 三字段（12 字节），不写新控制状态；首次起步不携带恢复退出历史。
- Reset/Stop/重新起步改变私有 `s_control_generation`。运行更新首先记住代次。
- 只在 RR 更新时进入短临界区，确认 active 与代次仍匹配，再一次完成计数观察、RR owner/bias 选择、RR PI/状态复制。其他三轮 PI 不放进这段新增锁。
- 输出提交及本轮计算的故障提交也校验代次，旧一轮不能覆盖 Stop 后的新一轮或产生替代故障。没有持锁等待串口、记录日志或执行延时。
- FreeRTOS `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY=5`、USB IRQ=5 均未改；安全任务/普通任务在临界区后执行。PC13 急停 EXTI IRQ=4 仍可打断，ISR 直接锁存并关断功率级，不调用新观察接口/RTOS API；原 MotorDriver 的急停拒绝写入逻辑保留。

新增确定性交错测试覆盖：快照返回时停车、初始捕获后停车、RR 解锁时停车、输出提交后停车、RR 内提出的待处理任务停车；分别模拟 STOP/health/transport、普通及回绕时钟，共 30 种。另覆盖两种停车后立即新起步和一次未被屏蔽急停硬关断。结果 RR 退出历史/积分/临时项不复活，旧输出不覆盖新代次。

这不是任意 IRQ/所有驱动的形式化证明，也不是实测锁占用时间。新增保护针对本次 RR 事务与输出/故障提交；没有声称重构了其他三轮全部私有状态并发。正常实时性与 USB 连续性仍需烧录后读取 timing/stack/drop 指标确认。

## 6. 用户下一步

1. 电机 VM 关闭，按现有流程手动烧录上述 HEX；不动 CubeMX。**用户要求的全片擦除会擦掉 IMU Flash 偏置**，不是本候选改变存储格式。
2. 烧录并重新上电后先看启动横幅是否为 `0.18.21-rr-recovery-exit`，再进行只读状态检查。
3. 保持车体固定、完全静止，按已有 USB 校准流程重新校准 IMU，并断电重启确认 `bias=1`/恢复成功；没有只读证据前不把零偏丢失解释为新漂移故障。
4. 另行确认安全条件后先架空检查，再小次数同条件落地对照。目标/供电/时长保持一致，记录四轮 target/measured/raw/PWM/FF/P/I、timing、stack 和协议计数，重点看 RR 恢复是否更柔和、会不会较早撤力又停住。异常或故障立即结束，不自动清故障重复试车。

在完成上述实板检查前，ROS 侧不应据本软件候选继续导航验收，也不需要修改几何、协议、IMU 或安全门控来配合它。
