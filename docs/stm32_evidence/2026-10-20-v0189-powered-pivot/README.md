# 0.18.9 有电池地面 pivot 对照，2026-10-20

结论：用户反馈“更连续、更均匀”。末段 LR 两方向均无零计数帧，右转总体误差下降；但 RR 左转完整记录到约 720 ms 连续零计数及随后 495 cps 峰值，仍不能标记低速控制通过。本次不继续改参数、烧录或增加运动测试。

## 条件与身份

- 用户报告烧录 [0.18.9](../../STM32_REAR_RESTART_TIMING_0.18.9_20261020.md)。未回读 Flash、未重新捕获 Boot Banner；trace 中后轮 80/40 ms 恢复及运动后提前交接与候选行为吻合，但不是独立二进制身份认证。
- 先只读 GET_STATUS，确认 COM4/COM8、IDLE、四轮静止、fault=0/0、供电约 10.758 V。用户随后确认四轮落地、约 80 cm 空间、无人接触，可以测试。
- 左右各一次：vx=0，wz=+200/-200 mrad/s，各 6 秒、20 Hz 指令，每方向 120 条。停车并读完 TRACE END 后才继续。
- CH340 在 open 前 DTR=False、RTS=False，并在测试期间保持连接；没有主动复位。
- 左转供电遥测 10406..10758 mV，右转 10384..10747 mV。非严格受控电源/摩擦实验，不把单次对照当成全部因果验证。
- 每方向 128 帧 trace：127 ACTIVE、1 STOP；完整四轮数据，源间隔恒定 20 ms。左 ACTIVE 为 81762..84282 ms，右 120782..123302 ms，均仅覆盖末段约 2.52 秒；全程另有 USB 原始计数和速度。

观察与推断需分开：

- 已观察：再启动先补 43.7‰，80 ms 后加 10‰，再过 40 ms 达到原 60‰ 上限。算法确实提前加码了，不是仍在等待旧 300 ms。
- 已观察：补偿达到上限后，仍约 0.5 秒没有编码器增量，期间积分和 PWM 继续增加；随后原始速度快速达到 400..600 cps。
- 已观察：转起后的交接让 FF 降、I 升，83322/83342 ms 的 FF+I 均约 184.3‰，总支撑没有随“退出启动状态”同步下降。至 83482 ms 仍约 175.2‰，超速 P 已在减力。
- 设计复核点：现有平顺交接是为了避免撤补偿导致再次停住，但把启动力转入积分/残余 bias，也可能让启动所需的大支撑在转起后保留过久。缩短状态保持并不等同于实际卸载；只继续改等待时间不足以检验这件事。
- 尚未证明：机械摩擦/四轮耦合、电流限制、轮地相对运动等的各自贡献。PWM 是控制指令，不是电流或有效力矩；不能根据这段日志就判定电机损坏、供电完全正常，或纯软件问题已经定案。

后续应优先复核“短时启动力”和“稳态负载支撑”是否需要分开管理，并设计有斜率/限幅、可回退的退出规则；不要再次仅统一增大 KP、补偿幅度或修改 ROS 有效轮距。若要继续改固件，需要针对上述事件的离线边界测试和同条件实板证据，不能承诺下一版必然解决。

- 240 条速度命令最终全部接受，拒绝 0；fault=0/0。
- 主机 CRC=0；固件 CRC/RX overflow/TX drop=0。
- 日志控制时序 motor_dt=20..20 ms、safety_dt=10..10 ms、overrun=0/0、log_drop=0。
- 两次 STOP 后 IDLE/EXPLICIT、请求速度和四轮速度均 0。
- 最终 STATUS 源时间 157126 ms，flags=0x0150，四轮速度 0。
- 本轮没有重做物理拔线、急停或掉电。未校准 IMU，bias=0；本轮不以 IMU 验收角度，交 ROS 前仍需显式校准保存。
