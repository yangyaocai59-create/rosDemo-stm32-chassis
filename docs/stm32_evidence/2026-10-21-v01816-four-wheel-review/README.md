# 0.18.16 四轮联动与 LM2596 供电路径离线复核

日期：2026-10-21，Asia/Singapore。本轮只读取既有文件并生成分析资料；没有打开串口、发运动/清故障/校准命令、修改生产固件、编译新版本或烧录。用户最新补充：电池与 D24A 之间的降压模块为 **LM2596**；实际模块照片、持续/峰值输出能力、当前输入电压尚未取得。

## 结论与优先级

不继续仅凭 LF 均速改善追加补偿。现有证据同时存在 LF/LR 重叠掉速、RF 独立掉速和恢复超调，不能把它们都归因于 LF 一项参数，也不能只凭芯片型号断定供电不足。下一步先核实电源路径的输入/输出电压及模块规格，再决定是否需要新的控制候选。

这不是宣称软件已经没有问题。控制器在低速带载下的补偿增加、撤回和恢复仍可能参与周期波动；但供电、机械负载、驱动端行为与控制之间尚未解耦，继续用单次实测反复加补偿不足以完成根因定位。

## 可复算证据

输入为 [原始落地采集](../2026-10-21-v01816-ground-pivot/README.md) 的 `capture/`，不是新的实车运行。执行：

```powershell
python docs/stm32_evidence/2026-10-21-v01816-four-wheel-review/review.py
```

[review.py](review.py) 仅使用标准库文件读写，不导入串口模块；生成 [review.json](review.json)，包含输入 SHA256、事件明细、USB 累计计数和电压帧。脚本还核对 USB WHEEL/BATTERY 的 payload 字节与已解码数组，核对 .16 交付清单中的 135 项文件以及 HEX SHA256。此次全部相符，未改变生产源码或烧录文件。交付 HEX 为 `e67a36800caf447839c2a68a5bcdcf8fac18286085b37251844e97954cab2ede`。

127 个 ACTIVE 帧覆盖 MCU 270322～272842 ms，间隔 20 ms，只有末段约 2.54 秒，不能推断整个起步。请求/应用均为 vx=0、wz=-200 mrad/s，打印目标四轮为 `[160,160,-160,-160]` cps，STBY=1、fault=0，四轮 PWM 每帧均非零且保持目标方向。

|事件|连续 dc=0 的首末帧 ms|按帧计账时长|PWM 首→末，单位‰|
|---|---:|---:|---:|
|LF 完整区间|271562～271802|260 ms|136→175|
|LR 完整区间|271622～271762|160 ms|94→138|
|RF 完整区间|272142～272342|220 ms|-119→-163|

首末帧的时间差与“按帧计账时长”相差一个 20 ms 周期，不能混用。RF 另有窗口首尾截断区间及单帧零计数，完整列表见 JSON；截断事件不能声称已取得完整持续时间。零计数不是独立视觉证明，不与用户“流畅”的现场反馈强行等同。

### LF/LR 重叠掉速

USB 同源累计计数交叉检查：271602～271762 ms 多个快照中，LF 保持 680、LR 保持 860；同段 RF 从 -577 继续到 -604，RR 从 -983 到 -1011。说明不只是 UART 打印、ROS 曲线或 LPF 单独制造了掉速外观，也不符合四轮全局计数服务一起停止；但 USB/UART 共享硬件编码器，不能排除真实反馈链路问题。

LF 在掉速前确有轻微撤载：271342～271422 ms FF 从 126.2 降至 124.2‰，不是此前旧版快速大幅撤载的同等情况。掉速后 PWM 持续增加。LR 掉速前 FF 保持 68.9‰，并无同样的前馈撤回；其近静止再启动补偿在 271722 ms 才上升，时间上晚于计数消失，不能倒因为最初掉速原因。左轮事件重叠提示必须看整车耦合，但不能据此猜测两个左轮属于同一驱动芯片或确认共同电源故障。

### RF 恢复与超调

RF 在 272142～272342 ms 无新增计数时，PWM 绝对值从119逐步升至163‰，不是固件撤掉输出。272362 ms 出现计数，272402 ms 反馈约 -126 cps，272442 ms 到 -240 cps，272462 ms 到 -271 cps（目标打印 -160）。恢复期间存在补偿增加、随后撤回与轮速超调，仍需在供电确认后评估恢复策略，不以平均速度替代连续性验收。

## 底层复核的边界

- `motor_driver.c::MotorDriver_SetCommand`：同方向非零更新写 CCR；不会每次主动把方向脚清零或拉低 STBY。零命令/换向才进入方向保护。末段 trace 没有方向反转或 PWM 零值证据。
- `encoder_service.c`：按各定时器位宽读取、差分及正向归一化；右轮继续计数，不支持全局采样任务暂停的解释。
- 已有记录中请求没有断续、控制周期无超期、STBY 未关闭、USB 错误为零。不代表示波器已证明 PWM 引脚、驱动输出或供电从未瞬断。
- 软件 PWM 是占空比命令，不是电机端实际电压、绕组电流或扭矩测量；即使未到 300‰上限，也不能推出供电肯定充足或电机肯定没问题。
- `wheel_speed_control_config.h` 明确早期空载 FF 来源于“未核实的 12 V 假设”，不是当前供电下完成的带载标定。没有依据直接套用 12/V 电压补偿或提高上限。

## LM2596 这一新增信息意味着什么

TI 官方 [LM2596 数据手册 SNVS124G](https://www.ti.com/lit/ds/symlink/lm2596.pdf)，第 1 页、第 8 页 Figure 7-6、第 33 页 9.4.3：芯片是降压型、额定输出能力 3 A；稳压需要输入输出余量，散热设计取决于工作条件。由此可推知，输入低于所需输出时不能靠调节旋钮保持 12 V。

这些是芯片资料，不是用户实际第三方模块的验收证书。板上电感、二极管、铜箔、接头、散热和实际器件均未知；不能把 3 A 写成整块小模块无条件持续能力，也不能凭名称给它另定“只能 2 A”的硬上限。当前没有四电机电流数据，不能计算或宣称总需求已经超过 3 A。

电池→LM2596→D24A 的供电路径值得优先核实：若输入余量不足，或实际模块在当前负载下出现压降/限流，便可能影响电机输出。**这是待验证假设，不是此次停顿的确诊。** 共同母线问题也不必表现为四轮同时完全停止，故右轮继续转既不能证明母线异常，也不能单独排除它。

### 为什么现有遥测不够

`battery_config.h`/`battery_monitor.c`：每100 ms集中取16次 ADC 平均，再作 `filtered += (sample-filtered)/8`；USB BATTERY约2 Hz上报。供电 mV 从滤波值换算，不是瞬时最小值。这一级 IIR 的名义时间常数约0.75秒（100 ms理想等间隔），额外上报间隔进一步限制可见性。

此次整段报告10.384～10.703 V；末段271327 ms为10.395 V，271727/272327 ms为10.384 V。不能据此认为260 ms事件有同步电压证据，更不能排除更短的跌落。D24A采样不是当前电池输入电压；不能拿它当电池电量或推断电池应立刻更换。

## 下一步最小检查（尚未实施）

1. 用户提供模块正反面清晰照片、标称规格，说明它是否还给其他设备供电。核实实际电路，不先买器件或改线。
2. 不运行电机，确认无运动程序，使用万用表直流电压档分别记录：模块 IN+ 对 IN-、OUT+ 对 OUT-、D24A VM 对其电源 GND。若需夹线，先断电固定绝缘夹，再上电读数；不要边转轮边拿表笔。
3. 若需要带载比较，再另行确认测试和安全条件，保持 .16 固件及同样目标不变。先观察输入、输出及 D24A 端电压；普通万用表的平稳读数仍不能排除快速瞬态。必要时由熟悉测量的人用示波器/合适电流探头补充，不把没有同步能力的数据强行按20 ms对齐。
4. 输入也跌落优先检查电池/保护板/输入线；输入稳定而输出跌落优先检查模块及稳压余量；模块输出稳定而 D24A 端跌落优先检查连接。三者看似稳定仍需考虑带宽、驱动端、机械和控制，不能直接判软件唯一根因。
5. 电源路径核实后再决定硬件调整或控制候选。暂不增加PWM/积分上限、不降低安全门槛、不改编码器/USB/IMU，不自动重试。

禁止把电流档表笔跨接电源正负极；禁止将 VM/电池接到 STM32 3.3V 或 ADC；禁止在未核实电池满充电压、驱动和电机额定值、保护/保险及其他负载前直接短接或绕过模块。以上均为计划，不是已执行的实车验证。
