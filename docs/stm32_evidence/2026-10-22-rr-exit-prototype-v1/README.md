# RR 恢复退场离线原型 v1（不是固件发布）

2026-10-22，Asia/Singapore。用户同意在 0.18.20 落地失败记录之后，先做 RR 恢复退场离线原型。本目录只存放冻结副本、原型和离线证据，**不能直接拿去烧录**。

## 结论

离线检查通过：在记录的相同编码器反馈及可匹配的初始状态下，RR 临时补力比 0.18.20 提前 **20 ms** 开始撤减，并提前 20 ms 撤完。未提高目标、PWM、积分或共享补力上限；其余三轮的回放导出字段一致。实际 fault manager 的 408 组配对模拟未增加堵转停车延迟。

这不是实车改善结论。车轮反馈是固定输入，不会因新 PWM 而改变；不能据此声称停顿、突然加速或物理负载问题已解决。当前板上仍按用户报告为 **0.18.20-rr-running-recovery**，其[落地 RR 停顿/恢复实测](../2026-10-22-v01820-ground-left/README.md)仍是失败状态。

本轮未修改正式 Application/Core/Tools 源码，未升版本，未链接固件、生成 HEX/BIN、打开串口、运行车辆、复位、清故障、校准、刷写、提交或推送。只编译执行了 native 外设桩测试和未链接的 Cortex-M4 对象。

## 原型改动范围

`baseline/` 的 15 个文件逐项匹配 0.18.20 发布清单；`prototype/` 仅以下四个副本不同：

- `chassis_controller.c`：从已有、已验证 valid 的轮速快照取 RR 增量、实际采样周期和时间戳；普通 PI 反馈仍为原滤波值。
- `wheel_speed_controller.h`：增加内部 RR 计数观察接口；不改变公共状态结构或 USB/trace 布局。
- `wheel_speed_control_config.h`：仅增加退出证据采样 15..30 ms、确认 40 ms 三个宏。
- `wheel_speed_controller.c`：RR 正向 PIVOT、已有 running ownership 下，短窗口计数辅助补力退场。新私有状态 40 字节。

不动编码器采集、原滤波器、USB、IMU、其他轮控制、正常直行、RR 反向或 first-start 策略。`fault_manager.c` 与冻结 0.18.20 **字节一致**。

### 退出判据

1. 只接收 15..30 ms 采样；数据年龄不超过一个采样周期。拒绝重复、倒序、未来、过期、零/过长周期、超过 3200 cps 的异常计数；无有效新数据时退回原滤波策略，不新增故障。
2. 两个连续、同正方向样本，按实际周期加权，形成 30..60 ms 计数窗口。窗口速度与最新单样本速度都必须超过 `target + max(20 cps, 10% target)`，连续累计确认至少 40 ms。
3. 标称 20 ms 下使用两个重叠窗口，即通常需三个连续样本；不是两个统计独立窗口。单个尖峰后跟零/低速/反向样本不能完成确认。
4. 已接近目标、原始窗口明显高于滞后的滤波值时，先暂停继续增大临时补力和 A→I 转移；确认超速后按原 400‰/s 撤减临时量，不把它继续转入 I。普通 PI 仍使用原滤波值。
5. 退出锁存至原有稳定再武装条件；新计数仍提示超速/加速矛盾时不允许用“滤波已稳定”提前再武装。再次完全停住不会无限重启临时补力。缺失证据仍保留原滤波回退。

保留 PWM 300‰、I ±50‰、正向 I 与临时补力共享 60‰、PWM 1000‰/s、补力增长至多 250‰/s、600 ms 有限 episode、零旧 bias 的 ownership 交接和全部停车/故障门控。没有把临时退场和安全 ownership 解绑。

## 历史输入回放结果

依据[前一轮实际 C/滤波复核](../2026-10-22-v01820-running-review/README.md)的条件化种子，沿用原始 127 帧 ACTIVE、20 ms、300 mrad/s 左转记录。滤波、dc 和 target 完全相同；未把新 PWM 反过来当作真实新轮速。

| 同一时刻（MCU ms） | .20 临时量 / I / PWM（‰） | 原型临时量 / I / PWM（‰） |
| --- | --- | --- |
| 162742 | 47.85 / 12.15 / 163 | 47.85 / 12.15 / 163 |
| 162762 | 47.05 / 12.95 / 159 | 47.85 / 12.15 / 159 |
| 162782 | 46.25 / 13.75 / 158 | 39.85 / 12.15 / 150 |
| 162802 | 38.25 / 13.59 / 144 | 31.85 / 11.99 / 136 |
| 162882 | 6.25 / 12.11 / 102 | 0 / 10.51 / 94 |
| 162902 | 0 / 11.56 / 92 | 0 / 9.96 / 90 |

原型在 162762 ms 暂停 A→I，162782 ms 确认退出；.20 等滤波超目标至 162802 ms 才进入原有退出。原型 162882 ms 撤完，.20 为 162902 ms。低/中/高打印量化种子均得到提前 20 ms；**两者全段峰值 PWM 均为 169‰**，不能声称降低了最初峰值或缩短最初停转间隔。

临时量未立即下降的 162762 ms 是暂停 I 转移，不是新增补力；同一时刻 I+A 保持约 60‰。原型只调整恢复后的退场，并未证明最初摩擦停顿的根因。

## 测试与证据

完整命令与输出见 `test_run.log`；汇总和文件 SHA256 见 `verification.json`。

- 新策略 7 组：短窗确认、限速撤减、不转存 I、有限退出/稳定再武装、单尖峰、量化、正反方向、目标变化、tick 回绕、缺失/重复/倒序/过期/未来/极值输入、采样边界、30,000 次对抗更新，以及目标 20..1600 cps 下退出后再次完全静止。
- 新实际 chassis/runtime 外设桩 1 组：退出/渐退期间的 STOP、零速、断链、health fault、急停、250 ms 超时、控制超时、超速共八类立即停车，各在普通及回绕时钟验证四输出归零、新历史清空。
- 原始 .20 runtime 测试未经改断言，在原型上 15 组通过；原前轮策略 11 组、前轮安全 2 组通过。
- 不提供快通道时，RR running 30,000 次更新输出/导出私有 running 字段与 .20 精确一致。
- 非修改范围 80,000 次更新，以及向观察接口注入计数后的同一范围 80,000 次更新，所有导出控制/旧 bias/LR 状态字段精确一致；first-start 10,000 次更新一致。这是指定输入下的导出字段比较，不是全部内存/中断并发证明。
- 实际、未修改 fault manager + runtime：I 种子 −50..50（每整数）及 5.85 × 普通/回绕 × 普通运行/先真实执行快通道退出，两套各 408 次；每对原型停车不晚于 .20。全部从持续零反馈开始 760 ms 触发（20 ms 离散调度下覆盖 750 ms 门限），mask=8、四轮关闭、锁存拒绝新运动，模拟显式清除本身不恢复旧命令，之后才接受新命令。
- 目标低于原安全门限 200 cps 的故障覆盖**未扩大**。上述 20..1600 cps 策略测试不能被误写成全目标堵转保护。保留原 legacy、LR 和 RR ownership 安全条件、原启动宽限/连续确认条件。
- 另重跑未改生产代码的 motion **79** 组、USB **20** 组；这些是生产 .20 回归，不能说成原型通过了全部 79 组。
- native 和 Cortex-M4 未链接对象均以 `-Wall -Wextra -Werror` 通过，无 warning/error。`ARM_object_sizes.txt` 和 `.su` 是对象/单函数静态栈数据，不是完整镜像大小、最坏调用链、RTOS 实际栈或实时时限证明。

首次试验曾发现“滤波 settled 再武装、但新计数仍超速”的断言失败；保留于 `initial_trial.log`。只修正离线原型的 settled 条件，未放宽原断言，最终全量重跑通过。不隐去该失败。

## 正式集成前还必须做什么

1. 单独征得集成/编译许可；仅将 RR 退场改动纳入候选，复核新观察/消费/复位状态与 FreeRTOS 安全任务的串行化和抢占边界。本轮 native 顺序桩不证明并发安全；现有 chassis 临界区布局未因本原型扩大，不能跳过此项。
2. 做候选全量构建、发布清单和烧录文件校验；不能以未链接 ARM 对象当作固件构建成功。USB、IMU和编码器继续不改。
3. 用户自行烧录前说明：其全片擦除是硬性条件，会清掉 Flash 中的 IMU 校准记录，必须按既有流程重校准并断电验证恢复；本轮未进行这些操作。
4. 另行确认架空/落地安全条件，使用一致供电、同目标和时长、小次数对照。只在实车原始计数、PWM/FF/P/I 和现场观察共同支持时判断是否改善；触发故障立即结束，不自动清故障反复重试。
5. 撤力较早也可能使带载轮重新欠速；现有回放不是物理闭环模型。若实车仍周期停顿，不以不断提高上限或改其他轮掩盖，回到负载、供电动态和轮速闭环证据分析。
