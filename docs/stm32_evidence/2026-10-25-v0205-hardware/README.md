## 真实 MCU 转向

最初 3 秒左转正常完成并停车，日志显示外环确实介入。但测试器随后两次等候调试串口追踪导出均超时，原 summary 保持 FAIL，见 `left_short_trace_unavailable`。用户烧录的是 Release 功能配置，其调试 UART 追踪命令不可用；未将导出失败删掉或改成通过。

随后通过显式 `--skip-trace` 进行两次 10 秒复测。主机只发固定名义 ±0.400 rad/s，角速度外环在 MCU 中运行。时间边界使用日志生产时的 runtime 转换时间戳；没有伪造 TRACE。USB 状态、四轮反馈、IMU 和 YAW3 日志分别保留。

| 8 个完整 1 秒窗口平均角速度 | +0.39199 rad/s | −0.40247 rad/s |

匀速窗口排除起步首秒和最后不足一秒，覆盖 START+1 至 START+9 秒，使用运动前静止零偏。不是逐个瞬时采样误差。左转停车后 IMU 基线均值变化约 3.98 mrad/s，对终点角度造成约 2.52° 的重算敏感度，需保留这一限制；不将终点角度差都归于编码器或打滑。

两次均显式停车到 IDLE，输出与四轮反馈为零，无故障、拒绝或通信错误增量。YAW3 在运动中 ready/valid，修正非零且在既有限幅内，motor/safety 无超期，IMU 源采样最大间隔 10 ms，无缺样。各检查见 `release_checks.json`。Release 无调试追踪，所以没有核对 TRACE 的四路 CCR 寄存器，不能声称检查过。

这些是单次双向有界试验，不是完整重复验收。0.20.5 尚未上板复测断链、超时停车、普通断电校准恢复和 180° 定角，本轮没有为逼近精度继续提高增益或放宽保护。最终 `final_readonly` 再次确认静止、故障 0、计数不变，串口关闭。

## VS Code 当前界面

安装工程本地状态扩展 0.1.1 到 **STM32** 配置文件，旧试装和一次重载辅助扩展已移除。当前 CMake 预设为 WheelV0205Release，ST Build Analyzer 指向版本化 ELF。实际重新编译后，POST_BUILD 自动发布新请求，扩展返回相同请求时间的成功回执；最后又同步校准和转向报告。

`vscode` 保存状态、成功回执、初次失败的旧错误记录及本地扩展源码/VSIX。成功回执时间晚于旧错误；旧错误仅供追溯，已从当前工作区清除。编译状态与用户报告的烧录状态分别显示，不推断外部烧录器已写入某个新编译哈希。

本轮新增的是构建后处理和主机工具，未再修改固件控制或 IMU 生产代码。新的普通构建 ELF/HEX 位于可重建目录，原 0.20.5 发布归档仍保持原哈希。比较两份 HEX 的实际编程数据，仅构建时间字符串的 5 字节不同，其余一致。没有因为界面同步再次烧录。
