# 用户烧录 0.20.4 后的首次只读检查

2026-10-25。用户在收到 0.20.4 文件后报告“烧录完成”。未捕获启动版本 Banner，不能独立确认 Flash 内完整版本；观察到新版 `YAW3` 日志，MCU uptime 与编码器计数已从重新启动计起。

本轮仅发 GET_STATUS，未发送运动、清故障、校准、复位或烧录命令。两个独立 5 秒只读检查和后续 6 秒全帧采集结果一致：

- IDLE，runtime/controller 故障均为零，四轮速度、输出与计数均为零。
- 供电约 10.47–10.48 V，ADC 错误为零。
- motor 20 ms / safety 10 ms，无超期；当前空闲栈日志为 1472 / 400。
- 串口报告 `IMU status=IO_FAULT WHO_AM_I=0x70 samples=0 errors=0`。
- USB IMU 帧共 105 个，均为样本时间 0、计数 0、状态 4、flags=4，即没有有效六轴样本；不是角度误差或基线尚未收敛。
- `YAW3 ready=0 valid=0`，角速度修正没有介入。

0.20.2 与 0.20.4 发布源码中的全部传感器文件哈希一致，当前工作区也一致，具体数量及哈希见 `diagnosis.json`。这并不能排除新固件的调度或集成影响，也不能把问题直接归因于硬件。只读协议没有 IMU 寄存器转储或设备电源控制入口；当前信息不足以确认初始化失败的具体寄存器或步骤。

目前不具备 IMU 角度和匀速验收条件，因此未进行转向或将普通轮速回退误报为新版外环通过。下一步由用户对主板和 IMU 完全断电重上电，再读取启动与传感器就绪状态，排除烧录后的残留供电状态。如果 USB 和电池均能供电，应都断开后再上电。没有要求重新校准、重新烧录或改线。

原固件、0.20.4 镜像与前一轮成功记录未改动。本目录保留未就绪现场，不与已完成的上位机 DLL 双向试验混淆。文件校验见 `capture_manifest.json`。
