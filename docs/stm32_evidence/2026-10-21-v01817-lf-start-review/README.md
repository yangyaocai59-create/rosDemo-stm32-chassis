# 0.18.17 LF反向带载起步：斜坡与恢复计时离线复核

日期：2026-10-21（Asia/Singapore）。用户仅授权继续离线检查。**本轮未连接串口、未清故障、未运动、未改生产固件或编译新烧录文件。** 编译的是桌面诊断程序；当前实板故障状态没有被本轮操作改变。

## 结论

现有代码确有可复现的起步补力时序限制：LF的单次300 ms恢复窗口在速度斜坡早期启动，负载支撑尚在爬升时，窗口已经开始消耗。达到最终0.30 rad/s目标前已用掉140 ms；窗口结束后，即使没有正常起转，临时项仍按规则撤回，正积分保持冻结，输出回落到约15.9%并等待失败保护。

这个解释能从零状态重放两次失败的全部173个ACTIVE帧，PWM、目标、应用角速度和滤波反馈的打印整数均一致，FF/P差在打印截断误差内、I全程一致为0。**解释的是固件为何发出这些命令，不是证明实车唯一根因，或证明调整保持时间必然能起转。** 电机端电流/电压、摩擦、驱动和机械负载没有新的独立测量。

不建议再提高整车目标或放宽失速保护。更合理的候选方向是：仅对LF首次带载起步，把首次起动与运行中失速恢复区分，使一次有界补力与速度/负载斜坡协调；不增加现有幅值权限，不影响停车，先离线原型验证再决定是否交付新固件。该候选尚未实施，需单独授权。

## 两次共同的时序

下表相对时刻以各次第一ACTIVE trace为0，并非USB首包或物理动作的绝对起始。

|相对时刻|应用wz|状态及含义|
|---:|---:|---|
|0 ms|0.015 rad/s|第一小目标，LF约-12 cps，PWM约-2%|
|60 ms|0.105 rad/s|近静止确认满60 ms，单次恢复计时开始；目标约-84 cps|
|200 ms|0.300 rad/s|达到最终约-240.64 cps；恢复计时已140 ms|
|340 ms|0.300 rad/s|两次均到本次实际峰值PWM约-18.3%|
|360 ms|0.300 rad/s|恢复计时到300 ms，未确认运动，退出恢复并开始撤回临时项|
|约420～440 ms后|0.300 rad/s|load到65‰、临时项归零、I=0，PWM约-15.9%|
|约1.7秒|0.300 rad/s|连续近静止失败保护置位，实板同时段LF故障日志并关闭输出|

“300 ms单次恢复窗口”不是1500 ms失败保护期限；二者作用不同，不能通过延长保护等待掩盖起转失败。

## 为什么窗口里的补力达不到现有允许幅值

控制器在LF目标首次超过20 cps时初始化load为当时的速度缩放上限（约14.66‰），不是立即赋最终65‰。之后目标上升虽提高了允许上限，实际load仍受确认/恢复速率约束。

恢复入口时load约18.66‰、临时项1‰。共享上升预算250‰/s在20 ms内总计5‰，其中近静止load恢复可用4‰，临时项通常只剩1‰；滤波微小运动中断近静止资格时，预算分配又有变化。两次合成支撑峰值相近，但分项不同：

|推断值|第一次|复测|
|---|---:|---:|
|最终目标首次到位时load‰|34.66|42.66|
|最终目标首次到位时临时项‰|20|12|
|本次最大临时项‰|39|27|
|最大可用临时/I共享余量‰|50|50|
|恢复窗口退出时load‰|54.66|65|
|恢复窗口退出时临时项‰|31|19|
|退出时recovery_ms|300|300|

本次未用满50‰余量不等于可以无限加力：这只是原策略时间、速度缩放和共享预算共同形成的结果。仍受300‰ PWM、50‰积分/临时共享、原方向load上限与故障规则约束。不能把“未满PWM上限”直接当电机端力矩足够或增加PWM一定有效的证据。

恢复退出后，仍近静止时load可继续向65‰恢复，但临时项以400‰/s撤回；没有已确认的同向运动，不能走转移临时项到I的运动交接。`hold_integral`仍为真，因此没有无限积分把轮子突然顶起来。

最后稳态支撑可从原参数直接核对：LF反向基础FF约81.619‰，load65‰，P约12.032‰，I=0，合计约158.651‰，取整为159‰（15.9%）。这解释了两次相同平台，不是USB指令掉线导致的周期归零。

## 回放精度与故障分支边界

- 第一次87帧：应用角速度/目标/滤波反馈/PWM打印整数全部一致；FF最大差0.09390‰，P0.08504‰，I0。
- 复测86帧：同样全部打印整数一致；FF最大差0.09390‰，P0.09545‰，I0。
- 两次最后ACTIVE回放均重建出`no_motion_ms=1500`、`recovery_ms=300`、`exhausted=true`、`recovering=false`、临时项0、`recovery_failed=true`，时间与实板故障日志对齐。
- 这增强了前轮有限恢复失败路径的解释；板上仍未直接上报私有分支，原>=200 cps的1秒宽限+750 ms堵转检测也可能同时满足，不能因此声称已排除它。
- 保留原阈值不变；日志和用户肉眼都支持真实起转困难，不把保护误称为“只要关掉就能解决”的误报。

## 下一步建议范围（未实施）

先设计/离线验证LF首次起步限定原型：

1. 区分“本次机动尚未确认运动的第一次起动”与“已经运动后再次掉速”，不让初次斜坡在低目标阶段就耗尽主要有效补力时间。
2. 在原幅值上限内安排一次可达的、有界的补力爬升与短保持；目标变化/微小计数不能无限重置或延长；确认真实同向运动或超速时及时退出/平滑交接。
3. 明确独立总时限，不延后现有1500 ms失败资格，不改变堵转故障锁存、STOP/零速度停车、断链/超时/急停的立即关闭路径。
4. 不提高PWM300‰、积分50‰、原方向load/临时共享幅值权限；不通过无限积分或反复kick尝试绕过失速。
5. RF和后轮不改，LF已运动后的协调规则尽量隔离；直行/滚动转向、编码器、USB、IMU、目标角速度和加速度限制不改。
6. 先验证相同记录输入下时序/幅值边界和未改模式的隔离；该比较不是新的轮速预测。是否生成候选、烧录和实车测试仍需后续授权及安全确认。
