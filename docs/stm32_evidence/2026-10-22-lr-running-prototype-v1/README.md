# LR反向运行恢复离线原型v1：拒绝合入（自动堵转计时退化）

日期：2026-10-22，Asia/Singapore。用户批准只做LR反向、已确认运动后的恢复协调原型和回归，再决定下一步。**总体结果：不满足安全计时验收，不生成候选固件、不合入生产。** 当前实板仍为用户报告烧录的0.18.18；本轮未打开串口、运动、清故障、校准或烧录。

原型的部分控制/隔离检查通过，不等于全部回归通过。尤其不能用STOP立即关断通过，代替自动堵转检测的时序审计。

## 范围与设计（仅本目录副本）

依据[LR/RF离线诊断](../2026-10-22-v01818-lr-rf-review/README.md)，只研究LR反向PIVOT的运行掉速，不改RF/RR/LF、首次起步、普通直行、编码器/滤波、USB、IMU或生产安全代码。`prototype/`相对冻结.18仅四个文件变化：

- `chassis_controller.c`：仅LR反向尝试从旧补偿移交到PI内协调路径；Clear/模式退出清理新状态。
- `wheel_speed_controller.c`：LR运行补力及I共享计账、有界介入/退场、确认/有限窗口和状态清理。
- `wheel_speed_controller.h`：增加两个内部C接口完成移交/清理，不改变原接口签名、状态布局或USB协议。
- `wheel_speed_control_config.h`：仅添加本原型参数，原增益/限幅数值保留。

移交要求：同向≥50 cps累计40 ms，旧启动恢复已非active，旧applied/steady bias均为0。尚有旧起步支撑时**保持旧策略**，不突然删除支撑，也不叠加一套新补力。因此本原型并不覆盖所有可能的LR历史；残留旧支撑的工况尚未迁移。

研究参数与逻辑：

1. 运行欠速超过`max(20 cps,目标×10%)`或接近静止，连续计账60 ms后开始一次补力。分离的短脉冲不累积。
2. 补力爬升上限250‰/s，移动欠速阶段按超出误差带的程度缩放；近停可用完整爬升速率。不是一入门槛就加60‰。
3. 临时项与已有同向I共享原60‰后轮权限；I仍限±50‰、PWM仍限±300‰，原输出斜率1000‰/s保留。正误差普通积分在协调期间暂停，避免重复加力。
4. 已确认同向运动且未超速时，可按40‰/s把临时项保守转交I，保持FF+I总和，不直接清除反向I债务。
5. 首个超速或反向运动停止增力；临时项按400‰/s撤减。一次episode计时600 ms后停止增力并有限退出，静止不重复尝试；恢复至目标附近累计100 ms且临时项为0才重新允许下一次。
6. 模式/方向/低目标/Reset和所有原安全停车清理新状态。额外caller旧bias不能与新所有者叠加，非法组合在状态变化前拒绝。

以上是被测试的v1，不是已批准的生产控制参数，也不是实际电机力矩模型。

## 规定反馈回放：命令更早，但不证明真实改善

输入.18那次落地左转的相同原始计数，保留相同目标/低通；环开头隐状态沿用诊断中的打印中点假设，且LR已确认运动、旧bias为0。只比较命令形成，不模拟真实轮子会如何响应。

- 旧恢复进入542863 ms；原型在542743 ms进入，提前120 ms。
- 原型临时项峰值约47.72‰；该窗口PWM绝对峰值154→135‰。
- RF条件性回放逐位相同，因为算法未改且反馈被规定为相同；**这不是实车RF也会不变或被顺带修好的证明**。
- 原型在部分停顿早期给出更多、后期更少的驱动；这种变化可能改变起转能力或超调，不能只用峰值下降判断实车更好。

数据见`recorded_commands.csv`、`recorded_comparison.json`。原始那8帧零计数仍被强制输入，不能把它们的存在/消失当新原型物理性能。

## 已通过的部分检查

- 80,000次未改范围逐字节对照：LF/RF/RR双向模式、LR正向及普通模式，含Reset/Prime、正反输入、0/1/10/20/59/60/100/101 ms、回绕时间输入。
- 10,000次首次起步及后续规定稳态对照，与冻结.18逐字节一致；不等于覆盖所有物理起步条件。
- 5组新策略断言：20～1600 cps、1～100 ms；确认/有限退场/不静止重试、共享权限、 opposing/zero/positive I、无效输入、反向运动、清理及30,000次对抗更新。
- 8类真实runtime安全出口（STOP/零速/断链/健康故障/ESTOP/250 ms命令超时/时序故障/超速），含tick回绕，均立即关断四轮、清理LR补力和I。
- 11组原前轮PI测试在原型上通过。
- 15组runtime兼容**子集**通过。`runtime_compat.c`明确只保留旧LR正向/RR反向恢复断言和其他通用runtime断言；LR反向的旧“立即整块恢复”预期由新测试替代，不能称旧全套runtime不变。
- 未修改的生产.18原测试仍47组运动、20组USB通过，表示基线没坏，**不是原型全部47组通过**。

旧完整runtime套件直接在原型上执行会在`test_runtime_motion.c:135`断言失败：它期望运行停顿第一帧立即按旧公式施加恢复；新LR反向先确认再渐增，预期本来不同。保留`legacy_runtime_compatibility.log`，未修改生产断言或将该套件伪报通过。这项兼容差异与下面更重要的安全计时回归是两件事。

## 阻止合入的审计结果

`audit_fault.c`使用真实runtime、真实fault manager和旧/新控制器、外围桩。先完成旧起步退出并使新路径有资格接管，在900 ms用原I交接API设定有效的历史积分，留100 ms供输出斜率稳定；1000 ms后规定LR持续零速，其他轮正常运动，持续保活。旧、新均不修改保护阈值；所有测试最终都锁存LR堵转、关断四轮并拒绝新运动。

下表时间为**持续零速开始到自动故障**，不是从上电开始，也不是实车结果。正I抵消本次负向驱动。

|-20|760|760|0|
|0|760|780|20|
|+6.7|780|1640|860|
|+20|780|1860|1080|
|+50|800|2360|1560|

不能只测“已有同向支撑I”的好情况：初次不单独控制历史I的审计两者均760 ms，加入反向I历史后才暴露显著退化。最终以表中六组有明确初态且输出已稳定的审计为准。

原因：原堵转判断除目标/低速/启动宽限外，还要求实际PWM幅值≥100‰连续750 ms。新策略的确认、爬升、积分暂停和有限退场会改变实际输出何时跨过这个门槛；**常量未改不代表自动保护时序不受影响**。在部分反向I历史下，临时项退出后PWM降到门槛以下，原连续计时被打断，之后普通I重新变化才再次进入计账。即使最终仍能停车，也不满足本次“不削弱原保护”的验收。

这不是永久漏报或失控的证明；本审计确认的是额外关断延迟，且存在有效初态反例，足以拒绝把v1直接做成实车候选。

`verification.json`明确记录`acceptance=REJECTED_SAFETY_TIMING_REGRESSION`、`automatic_stall_timing_not_delayed=false`、`ready_for_production_integration=false`。子审计程序返回0只表示完成采样和最终锁存断言，不能读成关断时序通过；顶层脚本会返回2以阻止合入/打包。

## 下一步建议（尚未授权/实施）

先补齐**新LR运行恢复状态与现有健康故障锁存/整车关断的衔接设计**，使有限补力退出不能掩盖持续无反馈。不靠提高PWM来维持检测门槛，也不降低原门槛或延长原允许期限；需要单独明确新的独立资格/失败上报如何与原保护并存，并用上述反例约束。

这可能需要在离线原型中增加LR恢复失败状态的消费路径，超出本轮“先做恢复协调、不动安全代码”的范围。因此本轮停在记录失败证据，不擅自修改fault manager或生成0.18.19。RF仍不改，首次启动和残留旧支撑迁移也不能宣称已全部解决。
