# 0.18.11 右前轮肉眼观察与日志对齐

日期：2026-10-20（Asia/Tokyo）。本次只执行一次 +350 mrad/s、6 秒左转，固件仍为 0.18.11。用户在安全距离观察后明确选择“明显停住过，随后恢复或突然加速”。日志同次记录到 RF 680 ms 连续零计数及恢复后超速；支持实体停轮现象，不再只用“轮子在转但编码器漏计数”解释。肉眼观察没有帧级时间同步，不把日志时长冒称为人工测得的停轮时长。

结论仍不是“电机损坏已确诊”或“只能靠加大 PWM”：机械/接地负荷、电源/驱动带载能力及前轮重启控制都需区分。另发现同一连续计数坐标下，三次长零计数的位置按每轮 1560 counts 折算非常接近，优先建议断电检查是否有固定轮位的发紧或擦碰。

## 条件与安全

- 延续用户此前确认的落地、供电和安全场地；本次说明只做一次 6 秒左转，用户同意并观察 RF。
- USB COM4、CH340 COM8。CH340 open 前 DTR=False、RTS=False，读取 trace 时保持连接；未主动复位。
- 执行脚本原有预检：先 STOP/GET_STATUS 并确认 IDLE、无故障、零速度；供电约 10736 mV。不是独立只读预检，本次没有宣称预检不含 STOP。
- 命令 vx=0、wz=+350 mrad/s、20 Hz/120 条，随后 STOP，确认 IDLE/轮速零再读取 trace。没有第二段运动。
- 供电遥测 10351..10736 mV，不是高速纹波、电流或电机端实测电压。
- 固件身份沿用用户烧录报告及配置行为；未回读 Flash 或取得新 Boot Banner。生产代码、参数、CubeMX、IMU/Flash、安全机制均未改。
- 完整 128 帧 trace：127 ACTIVE、1 STOP，四轮完整，dt/源间隔均为 20 ms。ACTIVE 时间 1395942..1398462 ms，只覆盖末段约 2.52 秒；全程另保留 USB 数据。

## 新线索：重复停顿的轮位接近

下列三次均为同一轮 +350 mrad/s 左转，在持续增长的 MCU 运行时间及编码器坐标中采集；工具没有发送计数清零/复位命令，记录没有新 Boot Banner。用当前名义标定 1560 counts/wheel-rev 取模：

| 抓包标识（目录时间） | 长零计数时 RF count | count mod 1560 |
| --- | ---: | ---: |
| 193201 | 1293 | 1293 |
| 193919 / LEFT1 | 1293 | 1293 |
| 194513 / 本次 | 4423 | 1303 |

第三次与前两次相差 3130 counts，即约两轮再多 10 counts，名义角度差约 2.3°。这值得检查轮胎/轮毂是否在固定角度碰擦、偏心或传动有周期阻力。

但样本少，1560 是名义轮周计数；重复的控制状态、负载历史或偶合仍可能造成相近位置。没有独立角度标记/视频或手转检查，不能据此认定齿轮、轴承、轮胎或驱动损坏，也不能认为每一圈必现。第二次重复测试 RF 连续的记录仍有效，不删除反例。

建议下一步：关闭并断开电机 VM，四轮架空固定后，从外观检查 RF 轮胎/轮毂/线缆是否碰擦，再缓慢手转并与其他轮对照，检查是否每圈某一位置明显发紧。减速箱本身存在阻力，不能把正常阻力直接判故障；不要强拧或在带电状态用手阻挡。需要用户反馈后才决定下一步运动或固件改动。
