可得的事实是“LF软件计数不变期间，软件请求、驱动接受值与CCR仍持续加力”；这不测量电机端电压/转矩，也不能区分实际微停、反馈丢失、原始定时器采集问题或正反净增量抵消。

## 判断与下一步

架空15秒实验出现前轮超目标且负积分达到限幅；本次落地出现非零输出下的计数平台。这两个工况均保留，不能只依据其中一个随意增加/减少全轮PWM。

用户观察基本连续，与持续零净计数构成需进一步核实的证据矛盾。当前优先检查实际轮动与编码器信号/定时器采集的一致性；不宣布机械坏、不宣布编码器硬件坏，也不宣布仅调PI即可修复。可先用本轮全程计数定位异常，再设计同步原始TIM计数/配置与A/B输入状态的有限诊断，必要时对照有标记的录像或逻辑分析仪。读取GPIO静态电平不能证明高频脉冲完整，应明确采样带宽限制。禁止按目标/IMU重建或修补编码器累计值。

本轮只左转，故障后没有追加动作。`capture/`保存USB原始流、payload、UART原始流及主机时间、完整TRACE2、动作摘要与离线分析。版本身份来自用户烧录声明和TRACE2特征，未主动复位或Flash读回。
