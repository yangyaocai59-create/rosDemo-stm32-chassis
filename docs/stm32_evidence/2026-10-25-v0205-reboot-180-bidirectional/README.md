# 普通断电恢复与左右各一次 180°

2026-10-25，Asia/Singapore。用户确认已经重新上电，并要求一次左转 180°、一次右转 180°。本轮只执行这两次运动，没有重试、重新校准、清故障、修改/编译固件或烧录。物理摆放未由用户指定，记录为 unspecified。

## 断电恢复

重新上电后 MCU uptime 约 32 秒，原始计数重新计起。只读检查中 IMU 有效采样、`bias=1`，静止 RAM 跟踪报告原校准温度 28.81°C，随后 YAW3 ready/valid 均就绪。本轮没有发送校准命令，现有固件只有读取兼容 Flash 记录后才会恢复这一校准温度和有效偏置，因此支持普通断电自动恢复已通过。运行中的 RAM 跟踪会微调偏置，不要求其数值等于保存时的每一位。

没有捕获瞬间启动 Banner 或逐字 Flash restore 日志，也没有直接读取 Flash 原始记录；不声称完成了全片镜像或存储区的独立读回。版本依据仍为用户先前确认烧录的 0.20.5。本次为普通断电，不能将其等同于全片擦除后仍保留校准。

## 双向结果

主机以有效 IMU 的采样时间积分，扣除每次运动前 3 秒静止零偏，接近目标时将名义角速度从 0.40 rad/s 逐步降低到 0.20 rad/s，达到 ±180° 后显式 STOP。原四轮速度环和有限幅角速度外环在 MCU 上执行；没有新增 MCU 定角指令，也没有使用主机 DLL 叠加修正。

| 指标 | 左转 | 右转 |
| --- | ---: | ---: |
| IMU 目标 | +180° | −180° |
| 发出 STOP 时在线 IMU | +180.05608° | −180.00423° |
| 发令时长 | 8.219 s | 8.140 s |
| STOP 后约 1 秒，统一窗 IMU | +180.39652° | −180.35783° |

| 完整静止观察后的在线 IMU | +180.30412° | −180.33029° |
| 改用运动后零偏的重算敏感度 | 0.34540° | 0.11161° |

统一窗以真实轮计数遥测为端点，从初始静止反馈至 STOP 后至少 1 秒的首个零速反馈；IMU 只对边界插值，未对编码器计数插值或缩放。表内角度为 IMU 参考，不是外部角度仪真值。两个不同方向的结果不能证明打滑模型固定，也不据此修改有效轮距或隐藏轮式/IMU 差值。

两次均恰好一次运动，达到目标后正常停车。状态无故障、拒绝或通信错误增量，最终四轮速度和输出均为零，IMU 源间隔最大 10 ms，无在线缺样。运动中 YAW3 ready/valid，修正量非零且有界；motor 20 ms、safety 10 ms，无超期。检查见各目录 `checks.json`。

这是 Release 固件，以 USB 遥测及带源时间戳的 runtime 日志验证；没有调试 TRACE 或四路 CCR 转储。最终 `final_readonly` 再次确认 IDLE、故障 0、速度/输出为零及计数不变，串口已关闭。

## 离线分析的重复样本处理

两次运动结束、所有比较和静止基线采集完成后，`final_stop` 阶段各有一个源时间相同、Z 值变化 1 mrad/s 的 SI 帧，符合现有静止 RAM 偏置跟踪更新。原离线脚本对采集文件任何位置的这种更新均拒绝，因此首次左转离线计算报错；运动控制和在线参考未报错。

离线脚本现按实际使用范围检查：转角窗口（含边界余量）以及运动前/后的基线内有冲突仍拒绝，只有完全不参与计算的窗口外更新单独记录，保留第一份源样本。两次被记录的更新均在 `final_stop`，未参与任何转角或基线计算；详见 `unused_outside_window_imu_updates`。自测验证窗口内、基线内冲突仍会失败。原始帧没有删除、重写或改为通过。

## 收尾

本轮满足 IMU 定角 ±2° 的单次双向目标，并完成此前待核对的普通断电校准恢复。它不替代长期漂移、不同地面负载或所有故障停车路径的重复验收。按用户“均匀、平稳、角度差不多”的当前用途，可保留 0.20.5 作为可用版本，不为追求极限精度继续修改参数。

VS Code 的当前硬件状态同步更新，但编译版本和烧录报告仍分别保留。所有历史固件与证据不覆盖。原始采集、比较数据、曲线及所用脚本均在本目录；完整文件校验见 `capture_manifest.json`。
