# RR 正转运行中恢复：离线原型 v1（2026-10-22）

结论：限定范围的离线检查通过，可以作为下一步申请集成的依据；**尚未集成生产代码、没有新版本固件、没有实车验证**。当前生产与已交付烧录文件仍为 0.18.19-lr-running-recovery。

本轮只操作本目录的副本，未打开 CDC/CH340、未发送运动/清故障/校准命令、未复位或烧录。只编译了主机测试程序和未链接的 Cortex-M4 对象文件，没有生成 HEX/BIN/ELF/MAP。

## 1. 范围与依据

依据上一轮诊断 [RR review](../2026-10-22-v01819-rr-review/README.md)，以及 .19 的落地左转记录 [capture](../2026-10-22-v01819-ground-left/capture/trace_parsed.json)。

该记录最后 2.54 秒有 127 帧 ACTIVE 内部 trace，RR 出现 100 ms 和 40 ms 两组零增量。用户现场反馈四轮连续。零增量不能单独等同机械堵转；回放不能确定最初阻力、电气或计数问题的根因。

原 .19 RR 运行中恢复在滤波速度降至约 19.72 cps 时才启动旧 restart 补偿；回放中旧临时补偿与同向积分的和一度约 62.23‰。这是分配协调问题，不是突破原 300‰ PWM 硬上限。

本原型仅改变 **PIVOT 模式、RR 正目标、已经确认转动且旧补偿完全退出后的运行中恢复**。在当前轴向下主要对应左转时 RR 的正向轮速，不等于修改所有前进控制。RR 反转、NORMAL/直行、其他轮控制算法、首次起转旧策略均不变。

只有五个原型文件不同于冻结的 .19：

- prototype/wheel_speed_controller.c：独立的 RR 状态、预算、渐进恢复和撤力。
- prototype/wheel_speed_controller.h：内部交接及只读安全查询；没有 USB/公开状态结构布局变化。
- prototype/wheel_speed_control_config.h：仅新增 RR_RUN 参数，所有旧宏定义保持原值。
- prototype/chassis_controller.c：限定范围交接与清理。
- prototype/fault_manager.c：保留完整旧保护及 LR 路径，再 OR 一个 RR 运行中持续低速保护。

baseline 的 15 个文件均与 .19 发布清单对应文件逐字节一致。生产 149 项源文件/测试哈希和四个交付文件哈希均保持不变。

## 2. 原型控制设计

参数是离线研究起点，不是已经实车调好的最优参数：

- 先有同向速度 >=50 cps 连续 40 ms；旧启动 pulse 不活动，applied bias 与 steady bias 都恰为零，才允许交接。
- 若首次起转留下非零旧补偿（例如积分已满仍残留补偿），继续旧策略，不叠加新补力；本原型不强行接管该情况。
- 明显欠速连续 60 ms 才启动渐进补力。误差带为 max(20 cps, 目标的 10%)；低目标近静止判据为 min(20 cps, 目标的 25%)。
- 临时补力 A 与同向积分 I 共用原 60‰ 权限：max(0,I)+A <=60‰；积分仍限制 ±50‰。测试浮点容差 0.001‰，回放最大约 60.000003‰。
- 补力上升不超过 250‰/s；有真实持续运动时以不超过 40‰/s 将 A 转入 I，转移不额外增加 A+I，并抑制同帧普通正向误差积分。
- 第一个超速控制样本（速度 >目标）即结束增力并撤去 A，撤力率 400‰/s；反向运动也结束增力。
- 单次 episode 的计时上限 600 ms，达到该值的首个更新退出增力，随后有限衰减；持续不动不会无限重试。A 已为零且连续恢复稳定 100 ms 才允许重新准备下一次。
- PWM 上限仍 ±300‰，输出变化率仍 1000‰/s，所有旧前馈/P/I/滤波/编码器/USB/IMU 设置不变。没有提高目标转速或 PWM 上限。
- STOP、零速命令、断链、健康故障、急停、250 ms 命令超时、控制周期异常、超速故障均立即走原四轮关断并清除新状态；不等待补力渐变。

## 3. 安全计时不退化

禁止以“临时补力仍活动”作为堵转计时资格，否则补力退出可能重置旧 PWM 门槛对应的计时。

原型保留完整 legacy 和已有 LR 判据，再增加：RR 正转运行中已经获得所有权、目标 >=200 cps、同向反馈 <目标 15%，经过原 1000 ms 启动宽限后，即使 PWM 已降至原 100‰ 门槛以下，也持续累计原 750 ms 检测时间。

新增路径与原路径共用同一个轮子的原计时器、故障码、锁存及四轮停机逻辑；没有自动清故障或自动恢复旧命令。查询只读，并要求在原故障管理临界区内读取；检查目标与最新 PI 目标一致，不宣称构成全部字段的原子时间戳快照。

**覆盖边界：**新增 RR 路径仍要求目标 >=200 cps，没有扩展低于该目标的后轮堵转覆盖。它是收紧保护，可能更早停止持续严重欠速的动作，不应为保持动作而绕过或放宽它。

| 故障后的行为 | 上述网格均验证 RR mask=8、四轮关闭、锁存、拒绝后续运动、模拟显式清除后仍不自动恢复，再有新命令才能动作 |

| 前轮回归 | 原前轮策略/交接/负载确认 11 组，以及实际前轮故障联动 2 组，使用原型代码通过 |

原版完整 runtime 测试直接运行原型时，在旧立即 restart 波形断言处失败，这是本设计有意改变的 RR 行为，不隐藏为全套通过。原始失败保留在 old_runtime_compatibility.log。runtime_compat.c 只对已有的两处 LR 排除增加 owned-RR 条件；run_tests.py 检查其余原始文件内容完全一致。RR 新行为由独立策略/安全测试覆盖。

ARM 未链接对象 text 总计增加 1844 B，BSS 增加 24 B。函数自身静态栈报告：UpdateWithMode 96 B、GetFeedforwardBias 104 B、ObserveMotion 112 B，均与冻结基线一致；新增 RR helper 104 B。这些不是最终链接大小、调用链总栈或实测 RTOS 高水位。

## 5. 同一历史反馈下的控制回放

以 127 帧原始 RR/RF dc 重建 20 ms 滤波输入，使用原实际 C 控制代码。baseline 与上一轮 .19 诊断回放逐字节一致；6 组种子/旧 restart 历史假设结果稳定。

- 原旧 restart 在 MCU t=1078642 ms 开始；新渐进补力在 1078502 ms 开始，提前 140 ms。
- RR 临时补力峰值约 49.12..49.21‰；同向 I+A 始终在 60‰ 浮点容差内。
- 同一反馈下 RR PWM 峰值：旧 170‰，新 166‰；不是把 PWM 提高来掩盖欠速。
- 1078802 ms 首次再次超速，新 A 立即下降；中间种子到 1078902 ms 已归零。
- RF 全部回放字段逐字节一致。

**限制：**截断 ring 的初始积分/滤波分数和 RF 恢复量来自可匹配打印精度的条件假设；新 RR 已具备 40 ms 运动资格也是交接分支假设，并非从丢失的启动历史直接观测。回放向新旧控制器喂相同的反馈，因此不会预测修改控制后真实轮速、零增量次数或车身转角，不能据此宣称机械问题解决或实车效果一定更好。
