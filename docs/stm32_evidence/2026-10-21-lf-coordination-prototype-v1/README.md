# LF 支撑协调离线原型 v1（不是固件发布）

日期：2026-10-21（Asia/Singapore）。用户批准范围：先做LF限定离线原型与安全验证。**本轮未打开串口、未发运动/清故障/复位/校准、未修改Application生产代码、未生成新HEX/新固件版本、未提交或推送。** 当前实板及烧录包仍为0.18.15。

依据：[.15 LF循环复核](../2026-10-21-v01815-lf-cycle-review/README.md)。原型在 `build/prototypes/lf_coordination_v1/` 隔离开发，可复现副本在本目录 `prototype/`，由独立编译命令引用；主CMake工程不会因此改用原型。

## 原型规则与暂定参数

只在已有LF/PIVOT/目标≥20 cps的分支中生效；RF保持.15。没有修改轮速估计、编码器、目标、后轮、USB、IMU、安全模块或板级配置。

1. 连续超速仍需原60 ms确认。确认后LF负载撤减速率改为 `clamp(超速超过原误差带的cps ×1.0,20,200)` ‰/s；小幅超速较慢、严重超速仍能快撤。P阻尼、普通I负误差修正、临时项退场仍立即响应，实际危险超速关断路径未改。
2. 临时项优先使用400‰/s合成撤减预算，负载项只能用余额；不是临时项400加负载200同时独立用满。I有向正值的额外撤减仍和负载共用其预算；反向I债务交接保留。
3. 已确认同方向运动（原40 ms/≥50 cps）、明显欠速且临时项已归零、恢复阶段已退出、I非反向时：按 `min(超出原误差带的欠速cps ×1.0,40)` ‰/s恢复负载，最多到原方向负载上限。这是**有界新增支撑**，不是保守重分类；同次普通正向I被冻结，避免双加力。I反向时先沿原路径解除反向修正，不同时加负载。
4. 近零确认时仍沿用原200‰/s负载恢复、250‰/s临时项自身上升限速，但两者总上升不得超过250‰/s；先分配负载恢复、再给临时项余额。例如典型20 ms步长，从旧的4+5=9‰变成最多5‰，不是抬高峰值。
5. .15已验证的运动欠速交接（临时项转I、FF+I守恒）、300 ms恢复阶段及有限退场、1500 ms连续近零失败、模式/符号/STOP清空保持。

上述合成变化预算针对固定目标/模式内负载与临时项的策略变化；**不含**P/普通误差I、旧反向I清零、模式/符号/目标切换导致的分类/限幅变化。最终PWM仍受原300‰幅值与1000‰/s变化率限制。不能把“400‰/s策略预算”误写成全部PWM变化上限。

原PWM/I/方向负载/临时项上限、PI增益均不变；有向I+临时项仍≤50‰。RF与后轮未采用上述新规则。

## 验证结果

`run_tests.py` 直接编译本目录原型，与现有真实runtime/chassis/fault-manager进行主机回归，**不是主CMake的完整固件构建**。

- 42个原生PASS输出组，包含42组内的大量参数化断言；另20个未变USB回归PASS输出组。不是62次实车测试。
- LF双方向，目标20/40/160/280/1600 cps，dt1/10/20/25/59/60/100 ms：合成增减限速、共享额度、幅值/变化率、运动中恢复不双加I、反向运动/误差带/反向I门控、持续超速最终撤完、连续近零有限失败通过。
- 现有真实runtime的STOP/零速/断链/健康故障/急停/精确250 ms超时/时序故障/超速八条关断路径通过，包括支撑交接中及时间回绕。
- 真实故障管理器的连续近零触发、全轮关断、锁存/拒绝命令/显式清除/新命令恢复，以及原后轮和NORMAL的旧堵转期限通过。
- 8000步原有前轮对抗边界测试通过；另80000步逐字段对照中，RF与后轮的NORMAL/PIVOT、LF的NORMAL在相同初态/输入下与冻结.15的浮点状态和PWM位级一致。不存在“LF从不同pivot历史退出后I仍必须等于旧版”的过度保证：控制算法未改，不同历史可能留下不同状态。
- 3份测试的原型副本只调整LF有意变化的精确速率/恢复预期；RF仍检查原200‰/s撤减。未修改Tools/tests里的生产测试，未删除安全/额度/期限断言。

ARM只编译控制器对象，零警告/错误。对象text 5506→6010 B（+504），bss均288 B；FrontSupport静态栈136→160 B（+24），UpdateWithMode仍96 B。不是完整链接镜像的FLASH/RAM数据，也不是板上任务栈/执行时长证明。后续正式候选需要完整干净链接和实板计时检查。

`compare_recorded_feedback.py` 继承前一复核的推定初态，把**完全相同**的小数轮速序列输入冻结.15和隔离原型；结果在 `replay_comparison.json` 与四份 `*_prescribed.csv`。这是规定反馈对比，不是新物理闭环仿真。

|---|---:|---:|
|最大单步有向FF+I变化，‰|12.4314|8.4314|
|规定序列最大PWM幅值，‰|185|183|
|规定序列最大FF+I，‰|180.6480|179.3813|

### 风险与未解决事项

- 更慢撤负载可能延长卸载超调；统一增力预算会降低某些近零恢复期间的增力速度，可能降低起步能力。这些是原型的明确取舍，不是已证明有利。
- 运动中负载恢复虽然与普通I互斥，仍比原算法某些时段给出更高支撑，可能在反馈延迟下超调。各上限未增加不代表每帧输出不变。
- 原始记录的初态/私有项为推定；负载、电源瞬态、轮胎阻力和编码器硬件因素尚未排除。
- 本轮只证明代码边界、隔离与原有安全路径；没有宣称整车低速转向已通过，也没有用“不报故障”代替性能验收。
