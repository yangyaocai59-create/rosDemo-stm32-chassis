# LR反向运行恢复原型v2：离线安全衔接检查通过，未合入固件

日期：2026-10-22，Asia/Singapore。用户同意继续研究“LR恢复失败接入既有故障锁存和四轮停车”。本轮仅修改本目录的原型副本和离线测试/文档；**没有修改生产Application/Tools，没有打开串口、发运动命令、清实板故障、校准、烧录或推送。没有生成0.18.19。** 用户报告已烧录的版本仍为0.18.18。

结论：修复了[v1](../2026-10-22-lr-running-prototype-v1/README.md)已发现的自动堵转计时退化，在本轮规定反馈和边界测试中未再出现延后。不是实车性能验收，不代表机械负载、供电或编码器故障已排除。v1拒绝合入的历史记录原样保留。

## 1. 原因及修改边界

v1将旧LR近停后的单次大补偿改成较早、有限、与I协调的运行恢复，但补力撤减可能令PWM低于原100‰门槛，重置原750ms堵转计时；部分反向I历史下关断延至2.36s。STOP立即停车通过不能证明自动堵转计时也合格。

v2**不再调整v1补力/P/I/前馈、PWM或斜率**，仅增加安全消费者：

1. `wheel_speed_controller.h/.c` 增加只读内部查询 `IsLrRunningSupportOwned(observed_target_cps)`。需要LR已移交新运行策略、目标反向且与最近PI更新的目标完全一致；拒绝NaN/Inf及目标不匹配。调用者沿用fault manager临界区，不修改状态或协议布局。
2. `prototype/fault_manager.c` 保留原堵转条件的完整表达式，另加窄范围条件后取逻辑OR。新增条件仅适用于上述所有权成立的LR反向运行，仍要求原1000ms运动宽限、目标绝对值≥200 cps、同向反馈低于目标15%、没有当次方向翻转；然后沿用原750ms连续检测计时。
3. 新路径**不要求当前PWM≥100‰**。这是有意增加保护，而不是声称原门槛完全没变：已确认运动的运行策略拥有控制权后，持续严重欠速即便补力已撤，也应进入同一个故障锁存。依靠整个运行所有权而非active/spent/600ms补力窗口，所以临时补力退场不会再打断计时。
4. 故障仍为现有`WHEEL_STALL`、LR mask `0x02`，由现有runtime健康故障流程关断四轮并拒绝运动。控制器状态清理、反馈恢复不会自动清除故障；显式清故障本身也不恢复旧命令。USB/IMU/编码器、前轮恢复失败机制和其他故障代码不变。

逻辑关系为 `新堵转条件 = 完整旧条件 OR 窄范围LR运行条件`。对相同观测序列，旧条件成立时新条件必成立，因而不能仅因新增条件而把旧连续计时重置；但新控制策略会改变真实反馈，所以仍需实车验证。

## 2. 保留的限定和风险

- LR所有权沿用v1：已确认同向运动，旧起步补偿已退出、applied/steady bias均为0才移交。有旧残留支撑时仍走旧策略，不突然删除或叠加支撑。并非覆盖所有LR历史。
- 新安全路径仍以≥200 cps为门槛；**未扩展20～200 cps以下LR的独立失败覆盖**，不能宣称所有低速下均有750ms停车保证。首次起步未获得所有权时也维持旧保护。
- 同向反馈恢复到15%门槛及以上会按原语义重新计时；不是跟踪误差保护，也不能检测所有打滑或编码器仍跳动的机械问题。
- 新路径可能比旧PWM门控更早终止持续欠速的带载动作。这是更严格的保护，不能用放宽750ms或提高PWM上限来掩盖实车故障。
- 从输出关断到物理轮子停止的时间、FreeRTOS实际调度/共享状态一致性及任务栈余量，没有在硬件上测量。安全查询须沿用现有控制器快照临界区调用；不是新增线程安全通用接口。

## 3. 自动失速审计：修复原有退化

`audit_fault.c` 用真实chassis/controller/runtime/fault manager，替代外设与反馈。先通过实际控制流程获得所有权，再在900ms通过既有API设置积分初态、留100ms收敛；1000ms开始持续零反馈。20ms采样，750ms名义检测在760ms处观察到触发。下表均为**零反馈开始到故障关断**的模拟时间，不是实车测量。

|---:|---:|---:|---:|
| −50 | 760ms | 760ms | 760ms |
| −20 | 760ms | 760ms | 760ms |
| 0 | 760ms | 780ms | 760ms |

扩展I从−50到+50每1‰一组，普通时基与`0xFFFFFC00`回绕时基各101组，共202组；v2均不晚于旧策略/旧保护，最大新增延迟0ms。每组还验证现有LR故障位、四轮输出关闭、400ms内持续拒绝运动、故障不自清、模拟显式清除不自启，以及新命令才重新进入运动。这些清除只发生于测试进程，**没有清实板故障**。

边界测试另以1ms观察验证1000+750ms精确边界；所有权/目标/模式/方向退出、NULL/非ACTIVE、恢复速度、重复160ms掉速脉冲、目标200及199.99、速度恰好15%、快照目标不匹配、计时回绕均有测试。私有状态注入仅用于隔离消费者边界，不能替代上述实际控制流程的所有权测试。
