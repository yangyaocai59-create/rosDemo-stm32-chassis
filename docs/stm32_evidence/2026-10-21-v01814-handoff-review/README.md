# 0.18.14 临时恢复补力与稳态支撑交接：离线复核

日期：2026-10-21，Asia/Singapore。用户批准先离线重审；本轮不打开串口、不发速度/清故障/复位/校准，不修改生产源码、不生成新 ARM 固件。当前板上仍为用户报告已烧录的 0.18.14，先前落地性能不通过的结论不变。

## 结论与边界

确认一个控制策略交接缺口：

1. 正向 I 在近零恢复入口被重新分类进 recovery；这虽然避免双份加力，也让原有稳态纠偏随后可能被当作临时项一并撤掉。
2. “同向≥50 cps、持续40 ms”仅确认轮子已动，并不等于达到约160 cps目标；一旦满足，就以400‰/s退出临时项。
3. 临时项非零时，正向欠速积分仍被冻结；没有一个等量的稳态纠偏接管这部分输出。移动期负载项的重建又仅能从已存在的 I 搬运，不能凭搬运创造净支撑。
4. 真实波动随后出现超速，60 ms确认后的长期负载撤减进一步参与变化。只改确认时间不能解决整个“补力—退出—再近零”的交互。

这些是代码和记录支持的现有策略机制，不是全部物理根因的证明。轮胎/地面侧滑摩擦、轮位、供电/驱动电流等没有独立建模或测量；不能据此宣布硬件一定正常，也不能承诺某个新策略一定能稳定实物。

## 真实 C 的确定性探针

`front_replay.c` 包含未修改的0.18.14控制C快照，只有电脑内存状态及规定反馈，没有GPIO/RTOS/串口或电机动力学。

LF/RF正反方向共4组：目标幅值160 cps，先用公共API建立已存在正向 I=20‰，再规定近零160 ms，随后规定持续100 cps的欠速运动160 ms。结果四组一致：

- 近零60 ms确认时，已有正向 I连同前两步新积分被转入临时项，I变为零。
- 临时纠偏总预算不超过50‰，探针达到临时项50‰后，开始给100 cps反馈。
- 第二个运动采样满足50 cps/40 ms移动确认，临时项开始每20 ms退8‰；欠速I多数时间仍冻结。
- 8个20 ms有效运动更新后，临时项归零，I仅为0.3‰，原有20‰支撑不再保留。`FF+I` 比近零之前低19.7‰，尽管这段运动始终低于目标且完全没有超速。

以RF反向为例，近零前同向`FF+I=144.5984‰`、补力峰值174.5984‰、上述欠速移动后124.8984‰。这些是**规定反馈下的控制代码输出**，不是实车额外做过一次动作，也不是新候选模拟结果。8步计账160 ms、首尾时间差140 ms，不误报为硬件精确延迟。

探针开发时首次只给近零140 ms，尚不足把临时项充到50‰，有关断言失败；随后按原代码的60 ms入口及5‰/步增量修正探针输入为160 ms。生产代码未改，最终四组通过，完整成功输出保存在`synthetic_probe.log`。

这也说明仅解除I冻结不够：在目标160、反馈100时，普通Ki=0.25对应15‰/s，远小于临时项400‰/s的退场速率（约26.7倍）。需要设计合成支撑的交接，不能把“允许积分”当成已经等量接管输出。

## 下一版建议范围（未实现、未编译）

建议先离线设计和比较一套前轮“有界临时补力—可撤回稳态支撑”交接，不再只改60 ms计时：

- 同向 I与临时恢复使用同一份既有50‰合成纠偏预算；不提高PWM/I/临时峰值、负载上限或车速，不叠加第二份纠偏。低目标时原有临时项缩放边界也保留。
- 已存在的、仍有依据的稳态纠偏不能仅因短暂近零就全部标为应撤的临时项。移动欠速阶段应平滑接管支撑，交接本身保持总输出连续，而不是只退临时项、同时冻结接管方。
- 不能把整段50‰脉冲一次锁入I或永久支撑地板；真正超速或卸载时，**合成支撑**也必须可有界快速撤回，不能只撤临时项却留下不可撤的正I。
- 50 cps仍只是“已运动”的信号，不把它单独作为“已达到稳态”的依据；也不简单把门槛改成160或延长固定补力时长，避免只保留更久的大力脉冲。
- 无运动时仍为一次有界恢复、有限退场和1500 ms失败关断；不因保留稳态支撑而使临时项永不归零、从而屏蔽失败报告。STOP/零命令/断链/超时/急停/故障必须立即清理全部局部支撑，不自动重试。
- 只动前轮PI/恢复交接，后轮、直行、几何、编码器/滤波、USB、IMU、安全协议不动。

这尚是设计要求，不是已选定且证明有效的算法。尤其“仅保留原I”对本次RF不够（它多次入场前的正向I本来很小）；“全临时项直接存入I”又可能重现卸载冲高。应先以合成预算、连续输出、欠速接管和卸载撤回作为可测试准则，比较小型离线原型，再决定是否建议生产0.18.15。

离线必须覆盖：已有I=0/20/50、低目标缩放、近零后慢动但未达目标、加速与真正卸载超速、反复停走、永不运动1500 ms、实际dt及模式/方向切换；所有上限和安全集成回归保留。即使固定反馈准则通过，因缺少已识别的电机/地面模型，实物稳定性仍只能在另行确认的架空→落地验证中评价。当前不生成烧录包、不转车、不发布稳定版。
