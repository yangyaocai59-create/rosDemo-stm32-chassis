# 0.18.11 同指令架空/落地对照

日期：2026-10-20（Asia/Tokyo）。用户报告手转/外观检查“都正常”，并提出架空测试；明确确认四轮架空固定、电源开启、线缆不碰轮、手远离轮子、串口助手关闭后，执行一次同指令 +350 mrad/s、6 秒测试。固件与参数不变。

现场反馈：“一直连续，没有明显异常”。数据也没有再次出现长零计数，并连续经过此前停顿对应的名义轮位。但不是控制通过：架空后 LF/RF 平均绝对轮速为 446/461 cps，目标仅 280 cps，反向积分已到限。固定 pivot 前馈对负载变化的适应范围不足，存在明确的参数/设计局限，不应继续只增加启动力。

## 条件与身份

- 沿用 `0.18.11-pivot-load-feedforward`，本轮未修改生产固件、编译、烧录或主动复位，也未回读 Flash/捕获新 Boot Banner。
- 与 [上一轮落地肉眼复核](../2026-10-20-v01811-rf-visual-check/README.md)使用相同 vx=0、wz=+350 mrad/s、6 秒、20 Hz/120 条指令，只改变用户确认的物理支撑状态。
- 实际轮速目标仍 LF/LR=-280、RF/RR=+280 cps，固件并不知道车辆架空；电脑端 `physical_setup=lifted` 只记元数据，不改变控制。
- COM4 CDC、COM8 CH340；CH340 打开前 DTR=False、RTS=False，完整记录期间保持连接。
- 先 STOP/GET_STATUS 确认 IDLE、无故障、零速度，预检供电 10769 mV。运动期间供电遥测 10692..10780 mV；落地上一轮为 10351..10736 mV。负载及电压并非完全相同，遥测不能代替瞬态电流/电压测量。
- 捕获 128 帧 trace：127 ACTIVE、1 STOP，四轮字段完整，源间隔/dt=20 ms。ACTIVE 时间 1881722..1884242 ms，覆盖末段约 2.52 秒，非全程 6 秒；全程另有 USB。
- 对比文件中的 baseline/candidate 指落地/架空，不是两个固件版本，不能当成固件升级效果。

## 固定前馈无法在空载时完全撤除

本窗前轮 FF 恒定，和地面相同：LF 后退 -152.5‰，RF 前进 +155.9‰。其中显式负载支撑分别为 -65/+60‰。架空时无需同等负载支撑，但当前 lookup 仅依赖模式、目标和方向，没有负载估计或因持续超速而撤减该固定项的机制。

LF 积分在全部 127 ACTIVE 帧为 +50‰，RF 全部为 -50‰，均用于反向抵消过量驱动，不是欠速时同向顶限。平均 P 分别约 +24.85/-27.07‰。实际平均输出可由各项重构：

```text
LF: -152.5 + 24.85 + 50 ≈ -77.65 ‰
RF: +155.9 - 27.07 - 50 ≈ +78.83 ‰
```

与 trace 平均 PWM -77.56/+78.93‰ 基本一致，逐帧舍入和使用浮点内部值产生细小差异。PI 在现有限幅内已无法将轮速拉回目标，只能依靠较大稳态超速产生的 P 项继续减输出。这是固定负载前馈与积分修正范围不匹配的直接证据，不是 ROS 单位或 USB 速度指令错误。

地面 RF 停顿时则是同向积分抬升到 +50‰、随后恢复超速。空载和带载两种相反的顶限状态说明，单纯统一增加前馈或扩大积分不应作为未经验证的修复。

## 对此前固定轮位线索的更新

全程 USB RF count 从 4837 增至 7585，净增 2748（约 1.76 个名义轮周）。区间包含 `5973/5983/7533/7543`，分别对应此前长零计数的模 1560 位置 1293/1303。起步 0.6 秒后，相邻 USB RF 计数始终递增，没有平台。

因此本次不支持“经过该轮位就必然卡住”的固定空载硬卡解释。结合用户手转正常，降低了这一假设的优先级；仍不能排除只有受地面侧向力/载荷时才擦碰或阻力突增。名义计数折算不是独立角度标定，记录中也没有外部位置测量。

## 建议的下一步，尚未实施

已有足够证据把控制优化重点放在前轮 pivot 的负载变化适应与重启恢复，而不是优先改通用编码器、USB、IMU 或 ROS 轮距：

1. 稳态转向支撑应能在负载减小、持续超速时撤减，不能只按目标永远施加满量固定项。
2. 真实近零速/无计数时的短时恢复，应与长期运行支撑、积分分开，具有幅值/时间边界；恢复后及时撤除，避免重新把瞬态变成长期积分残留。
3. 不扩大现有总 PWM/积分上限，不修改 250 ms 命令超时、真实 USB 断链、故障/急停直接停机逻辑；直行和其他模块保持范围不变。
4. 先定义和测试负载骤增/骤减、近零目标、换向、模式切换、计时回绕、STOP 等边界，再编译候选。实车需同目标落地/架空两边验证，既不能长停，也不能卸载后长期超速。软件候选仍不能代替带载硬件能力核对。

这是一份变更建议，不是已完成的算法或新版本承诺。本轮没有自动修改固件，需用户同意具体方案后再实施。
