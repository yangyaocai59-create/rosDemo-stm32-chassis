# 转向反馈容忍度：离线统一判定原型 v1（不是新固件）

2026-10-22，Asia/Singapore。用户降低验收目标为转向流畅、角度大致可靠，并同意先离线验证“允许短时波动，真正持续异常仍停车”。本轮**没有开串口、运动、清故障、修改生产源码、生成新HEX、烧录、提交或推送**。当前实板仍是用户报告的0.18.21，最近右转后保持FAULT，不应自动续跑。

## 先给结论

**可以在软件上区分“有计数的持续慢转”和“持续没有有效进展”，但仅放宽停车条件并不能证明这辆车会恢复流畅转向或角度正确。** 本原型的规则和边界测试通过；不将它包装成已经解决问题的0.18.22让用户再刷一轮。

最近右转：约5.235秒/IMU估计−48.44°提前停车，UART wheel_mask=0x04指向RF；用户报告四轮看起来连续，没有明显异常。右转未完成，原计划的左转取消，地面180°验收没有通过。最终FAULT、四轮零速、输出关闭、两端口关闭。发84条速度命令，83接受、运动停止过程中1条拒绝；没有清故障。

该轮完整内部环已保留。RF最后一个非零增量在3943943（dc=−1），随后26个连续20ms区间零净增量，覆盖520ms，最后仍ACTIVE的记录为3944463；其间PWM约−198逐渐退至−180‰，并非零输出。原保护在3944482锁存，属于严重欠速判定，不是因为角度差几度。

## 原型具体规则

| 条件 | 原型处理 |
| --- | --- |
| 四轮、正反方向 | 同一纯C函数；每轮各自状态，无轮号特例 |
| 启动 | 1000ms启动宽限，不改变输出 |
| 短时严重欠速（滤波速度低于目标15%） | 持续150ms后给内部WARNING；不是整车故障 |
| 没有新的同方向净计数 | 750ms有限期限后FAULT，不因重复快照或PWM下降而无限延后 |
| 有零星计数但持续严重欠速 | 最长1500ms故障上限；单个速度尖峰不能刷新为健康 |
| 恢复正常 | 速度及近期计数支持健康，持续100ms才结束该严重欠速事件 |
| 旧/重复/矛盾快照 | 重复快照不增加进展；陈旧、倒退、计数与增量不一致等报告证据故障 |
| 目标低于200 cps、非运行状态 | 明确NOT_SUPERVISED，**不是允许继续运行**；如集成必须保留已有低目标和其他安全路径 |

这些只是离线试验参数，不是已验证的电流/热安全范围。原型不发PWM，不改速度目标、积分、前馈、编码器计数、USB或IMU。稀疏脉冲也可能是噪声，不把“一次计数”当轮子健康证明，所以另有1500ms严重欠速总上限。故障保持锁存，闲置输入不自动清故障。

注意：这是改变**判定的依据与时间基准**，并不等于将750ms全局改成1500ms。相对旧保护，对仍有稀疏同方向计数的严重欠速，允许等待更久；对连续无计数仍有限制，部分场景也可能比旧滤波判定更早结束。

## 离线验证结果

- 严格本机C编译`-Wall -Wextra -Werror`：10组测试通过。
- `-O2 -fanalyzer`编译及同样10组测试通过。
- 隔离的Cortex-M4对象编译通过；**没有链接成固件**。
- 21组历史输入回放，包含上次成功左转、失败左转、失败右转四轮USB输入，以及可用的20ms内部环。
- 核对167项生产源码及四个0.18.21固件产物哈希，均未改变。
- Windows本机GCC的UBSan链接失败（缺少`-lubsan`），没有宣称消毒器验证通过；普通严格编译、静态分析及优化版测试结果另行保存。

测试覆盖400ms缺口后恢复、750ms无进展边界、启动宽限、微弱PWM、四轮状态隔离、正反转、32位时间回绕、较旧调用时间/较新生产者时间、重复/失效快照、64位计数溢出拒绝、稀疏脉冲及正反抵消计数不能无限延长严重事件等。消费者跳过生产者的个别20ms样本时，使用累计净变化，不把跨40/60ms累计差误比为末次20ms的delta；100ms以上取样缺口仍报告证据失效。

## 回放不能当实车成功

成功的约20秒左转，原型对四轮全段USB及尾段trace均未报故障。

失败右转的RF，原型在实际记录终点之前没有报故障。这**只说明新条件会多等，不说明原故障是误报**。实际轮子在旧故障之后已经停车，后续不存在“如果继续驱动会怎样”的真实数据。

为检查期限，额外构造了一个**明确标注的合成后缀**：假设旧停车点以后RF继续没有新计数、仍保持原目标与输出，并让滤波继续衰减。原型在3944703报无进展故障，比原故障3944482约晚221ms。该后缀只能证明等待不会无限延长，**不能证明真实轮子将在这约0.2秒里恢复，更不能把它写成完成180°的实测数据**。

失败左转同样在旧记录结束前尚未触发原型故障，也不能因此称为已修复。已知成功、失败记录都保留，不用一次成功覆盖失败。

## 尚未完成的集成条件

原型没有进入实际safetyTask，尚未替代生产固件中的普通堵转、前轮恢复失败、LR/RR专项路径；不能宣称实板四轮判定已统一。后续如要接入，至少需要：

1. 确认运行代次、目标、原始计数和PWM的快照对应，不能混用停车前后数据。
2. 处理已有前轮恢复失败锁存、低目标范围、速度无反馈注入测试，避免旧路径提前覆盖新策略，或新策略遗漏原保护。
3. 保留急停、命令超时、真实断链、任务健康及IWDG机制，并补集成测试。
4. 明确接受延迟停车带来的有限额外驱动时间，而不是把此变更描述为完全无安全取舍。

**本轮决定：先不交付只改停车阈值的新固件。** 当前证据更支持同时核查导致持续欠速/计数间歇的控制恢复逻辑，而不是通过延后故障就宣布验收通过。是否进行下一步生产集成或统一闭环修改，应另行说明范围，不能静默扩大。

## 文件与复算

- `prototype/`：纯C状态机、10组测试、本机stdin/stdout回放适配器；不依赖HAL、串口或电机驱动。
- `input_right/`：最近失败右转的原始记录和实际主机脚本副本。**其中主机脚本会控制实车，不要运行它。**
- `results/`：编译/测试日志、逐项输入及结果CSV。`SYNTHETIC_FROZEN_EXTENSION`名称明确表示旧停车点之后为假设数据。
- `verification.json`：各组回放结论、假设、生产哈希及限制。
- `capture_manifest.json`：完成后的文件封存，不含自身。

纯离线复算：`python docs/stm32_evidence/2026-10-22-pivot-feedback-policy-prototype-v1/run_review.py`。脚本只编译本机测试和隔离ARM对象，读取历史资料，不打开串口、不构建或烧录完整固件。

全段USB回放缺少PWM，使用0作为“未观测”占位；该原型不按PWM大小决定是否延期，所以这不是实际零PWM证据。固定目标±240用于启动后的常用测试区间，不能用来评估所有动态目标。尾段回放假设启动已完成且此前正常，未复原截断前的完整内部状态。没有真实机械负载模型、外部精确角度或A/B边沿记录。
