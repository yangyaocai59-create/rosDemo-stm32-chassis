# 线缆阻挡触发保护的原始记录

2026-10-25。板上为用户已烧录的 0.20.2；上位机运行初版 C 角速度核心，不是 0.20.3 MCU 验收。

`capture` 保存唯一一次受阻运动。LF 有实际 PWM 输出而编码器持续零反馈，轮反馈保护随后锁存并停车。采集报告 FAIL，最终已停车；没有自动清故障，也没有把这次失败当作改善证据。右前轮期间也出现短时反馈不足，不能只凭记录确定每个瞬态的物理原因。

用户随后说明“刚刚是因为线阻挡了轮子，可以继续了”。`operator_context.json` 保存这一上下文。确认四轮静止、输出关闭及供电约 10.56 V 后，只清除了一次已解决的健康故障。清故障原始记录在相邻 `2026-10-25-v0203-yaw-assist/resolved_wire_clear` 中。没有复位、烧录、修改编码器配置或放宽保护阈值。

该记录还暴露了旧版重复健康故障调用每 10 ms 重写事件环的问题；0.20.3 起对已关闭输出的同一锁存故障保持幂等，以保留首次故障现场。保护仍保持锁存，清故障条件不变。

这里的 DLL 和 `tested_sources` 对应受阻时的初版算法，系数与后续 v2/v3 及 0.20.4 不同。原始数据及失败均保留，目录清单见 `capture_manifest.json`。
