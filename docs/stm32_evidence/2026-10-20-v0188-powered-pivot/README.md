# 0.18.8 有电池地面 pivot 对照，2026-10-20

结论：用户反馈“更平稳、速度更均匀”。RR 两方向平均速度更接近目标、峰值和 RMS 下降，但左转出现持续至停车前的约 620 ms 连续零计数区间，前轮和部分总体指标退化。因此只算局部改善，不能标记低速控制通过，也不应据此交 ROS 作为最终稳定版本。

## 条件和采集完整性

- 用户报告烧录 [0.18.8](../../STM32_REAR_RESTART_0.18.8_20261020.md)；本轮未回读 Flash、未重新捕获 Boot Banner。后轮补差额/分级恢复的 trace 行为与候选逻辑一致，但不是独立二进制身份认证。
- 先只读检查 COM4/COM8：IDLE、四轮静止、fault=0/0、供电约 10.758 V；仅发送 GET_STATUS。用户随后确认四轮落地、约 80 cm 空间、无人接触，可以测试。
- 左右各一次，vx=0，wz=+200/-200 mrad/s，各 6 秒，20 Hz 指令；每方向 120 条速度命令。每次停车并读完 TRACE END 后才继续。
- CH340 在 open 前设 DTR=False、RTS=False，采集期间保持打开；本轮没有操纵启动脚或主动复位。
- 每方向 128 帧 trace：127 帧 ACTIVE、1 帧 STOP；完整四轮数据、源间隔恒定 20 ms。左 ACTIVE 源时间 67322..69842 ms，右 106362..108882 ms，各仅覆盖末段约 2.52 秒。
- 同时保留全程 USB 原始计数和速度。左转供电遥测 10384..10758 mV，右转 10384..10615 mV。地面摩擦、姿态和电源不是严格实验室受控量，单次对照不能证明所有变化都由代码直接导致。

再启动时先补 15.2‰，与前一帧 44.8‰ 支撑对应；300 ms 后加 10‰，再按 100 ms 增加，证明分级逻辑在工作。此段补偿尚未恢复到原 60‰ 上限就到达本次 STOP，无法据此判断恢复原上限后是否可以重新转起。

同一段原始计数持续为零，滤波速度也趋零，而目标仍为 +160 cps、PWM 从约 15.2% 增至 18.7%。它不是 ROS 停发命令或 USB 停车导致；“支撑补差额 + 300 ms 等待”对这次带载卡滞恢复不够及时，是下一步需要处理的具体行为。没有电流/独立转动观测，不能单凭编码器把机械卡滞、接触摩擦等进一步定性。

其他补偿再投入：LR 左转约补 52‰，LR 右转约补 29.6‰，RR 右转约补 51‰；并非所有再启动都降至同一固定补偿。0.18.6 FF/I 交接仍保留，退出时 FF 减少对应的 FF+I 相邻变化最大约 1.3‰，没有回到直接撤去 60‰ 的旧问题。

前轮代码未直接调整，但本次 LF/RF 跟踪指标有退化。四轮带载是耦合系统，不能因只改后轮就将前轮视为“已验证完全不受影响”；也不能靠继续统一增大 KP 或改 ROS 轮距掩盖这些指标。

## 通信和停车

- 240 条速度命令全部接受，拒绝 0；fault=0/0。
- 主机 CRC=0；固件 CRC/RX overflow/TX drop=0。
- 两次 STOP 后均确认 IDLE/EXPLICIT，四轮速度和请求速度为零。
- 最终 STATUS：源时间 142696 ms，flags=0x0150，四轮速度 0；没有未结束的运动命令。
- 本轮没有重做物理拔线、急停或掉电，不将历史安全测试冒充本次实板测试。
- IMU bias=0，与用户全片擦除流程一致。本轮未校准、未用 IMU 验收角度；交 ROS 使用前仍需显式校准保存。
