## 原始计数已排除什么

在114帧窗口内：

- 四轮配置检查`bad=0`，快照flags=0；检查范围内未发现TIM停用、编码模式/滤波/ARR/PSC或GPIO复用/时钟改变。
- 相邻原始采集CNT按16/32位回绕并方向归一后，与累计计数变化全部相符，没有一帧差分不一致。
- 运行中少量live相对sampled领先1个原始计数，符合稍晚读取；没有发现live持续推进而sampled停住。
- LF在71503～71923ms连续22个20ms区间dc=0，覆盖440ms（首末时间差420ms），sampled/live均65534，累计值-2，A/B瞬时电平持续2。PWM幅值159→187‰，CCR1335→1570，I从-2.8→-28.0‰，输出未切断。
- 同期LR存在220ms和160ms零净计数窗口，sampled/live同样停住，寄存器检查正常。此处为首次启动早段，不能与后来所有稳态事件混为一谈。

因此，在已捕获窗口没有“硬件CNT持续增加而软件累计漏加/ROS解码丢失”的证据。只要原始CNT没有产生净变化，继续修改累计、四倍频或上位机换算不能补救这件事。

尚不能排除真实轮子近停、编码器信号未到达、波形/供电/接线问题、输入计数器有效边沿丢失或区间内正反抵消。20ms读取A/B可能混叠，不是逻辑分析仪；bad=0也不能证明电气输入健康。用户之前对0.18.23的观感不能直接作为本次物理转动测量。本轮没有询问或自行补填观感。
