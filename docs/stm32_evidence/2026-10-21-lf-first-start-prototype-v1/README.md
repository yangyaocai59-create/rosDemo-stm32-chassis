# LF 反向首次起步：离线原型 v1（不是固件发布）

原型工作始于 2026-10-21，最终离线复核于 2026-10-22。用户授权范围是“先做离线原型和回归，再决定是否生成下一版”。本目录没有生成新固件版本，没有链接、烧录、打开串口、清故障或发送运动。

## 结论与边界

原型通过 47 组原生控制断言、20 组 USB 回归及 ARM 单对象编译。它给 **LF 反向 PIVOT 首次起步**增加有截止期限的补力保持；不是全车加速，不改目标速度、PWM 上限、其他车轮参数、编码器、USB 或 IMU。

两次记录的相同 LF 反馈输入下，原型能到达原有临时补力预算并保持约 100 ms；输出峰值由 183‰ 变为 209‰。这证明命令时序改变，不证明真实车轮能起转。更长、实际更高的输出意味着更多起步能量，不能用“上限未变”代替冲动、电流、温升和带载性能验证。

当前生产源码仍为 `0.18.17-rf-support-coordination`，没有 `0.18.18` 烧录文件。车辆最后实测仍是 LF 故障锁存，不能把本离线结果当作清故障或重新运动的许可。

## 依据

- [两次 LF 起步离线诊断](../2026-10-21-v01817-lf-start-review/README.md)：冻结 C 从零状态重放全部 173 个 ACTIVE 帧，打印 PWM/目标/反馈一致。旧恢复计时在目标爬升中提前消耗，临时项退出后留下约 159‰，I 仍冻结。
- [第一次落地失败](../2026-10-21-v01817-ground-left-fault/README.md)和[一次授权复测失败](../2026-10-21-v01817-ground-left-repeat/README.md)：LF 各仅 3 个计数；第二次用户确认基本没转或明显停住。原因不能唯一归结为控制器或机械/供电。

## 原型规则

仅 `prototype/wheel_speed_controller.c` 和 `prototype/wheel_speed_control_config.h` 相对冻结 .17 有策略修改，其余副本保持原样。生产 `Application`、现有 `Tools/tests` 和公开状态/通信布局不变。

1. 仅 LF 反向、原地转向策略、尚未确认运动时的第一次近停恢复有资格延长。LF 正向、RF、后轮、普通直行策略不使用该规则。
2. 从该策略阶段进入开始累计有效控制时间；特殊窗口绝对上限 600 ms，目标值变化不会重新计时。
3. 保留原 300 ms 恢复时限作为通常的最短计时条件；达到当时负载项上限及临时项可用预算后，尝试保持累计 100 ms，再退出。运动确认、首次超速或安全停车会提前退出；600 ms 截止也可在未获得完整保持时直接结束，不保证所有工况都有 100 ms。
4. 太晚进入近停恢复、无法在特殊截止内容纳原 300 ms 时，不启用延长，沿用旧 300 ms 分支。因此 600 ms 限制的是特殊延长，不是重新定义所有后续恢复的全局时限。
5. 原 60 ms 近停确认、50 cps/40 ms 运动确认、合成增力斜率、I 与临时项共享 50‰、方向负载上限、PWM 300‰、输出斜率及卸载逻辑保留。不靠额外正向 I 堆积实现延长。
6. 仍静止时只有一次尝试，不循环追加；确认运动后的真实再次停顿沿用旧 300 ms 恢复。模式、方向、低目标、零速或 Reset 清理私有状态；RF Reset 不清理 LF 状态。
7. 原 1500 ms 恢复失败条件、原堵转保护及全部整车安全关断保持。特殊补力不能越过 STOP、零速、断链、心跳超时、健康故障、ESTOP 或控制时序故障。

## 同反馈命令比较（非实车预测）

两控制器强制输入相同的原始计数，使用同一轮速滤波、运动斜坡及几何计算，不能模拟输出改变后真实轮速的反馈。

| 项目 | 第一次记录：旧 → 原型 | 第二次记录：旧 → 原型 |
|---|---|---|
| ACTIVE 帧 | 87 → 87 | 86 → 86 |
| PWM 绝对峰值 | 183 → 209‰ | 183 → 209‰ |
| 临时补力峰值 | 39 → 50‰ | 27 → 50‰ |
| 恢复进入到退出 | 300 → 500 ms | 300 → 500 ms |
| 全额支撑帧计账 | 0 → 100 ms | 0 → 100 ms |
| 原型退出时策略累计 | — → 560 ms | — → 560 ms |
| 恢复失败判定时间 | 549182 → 549182 ms | 1286982 → 1286982 ms |

100 ms 是五个 20 ms 控制周期的计账；不是两端时间戳相减的额外测量。故障时刻不变只适用于这里规定的反馈，其他真实运动情况仍按现有保护条件判断。

完整数值见 [recorded_comparison.json](recorded_comparison.json)，四个 `*_commands.csv` 为可复算输出；原始 trace 路径和 SHA-256 也在 JSON 中。

## 验证覆盖

- 47 组是离线断言组，不是 47 次实车测试；20 组 USB 回归使用未修改的生产协议代码，没有连接端口。
- 120010 次隔离更新：RF/后轮、LF 普通模式与正向 PIVOT，以及从相同已确认运动状态开始的 LF 双向序列，与冻结 .17 输出逐位一致。这不声称首次起步改变后任意历史下的积分状态也会相同。
- 目标 20/40/80/160/240/280/1600 cps、步长 1/10/20/25/59/60/100 ms；覆盖截止、晚进入、目标变化、不静止重试、运动/超速退出及后续堵转。
- 无效 dt/NaN 不推进状态，模式/符号/零速/Reset 清理；所有八条实际 runtime 安全出口在延长到 400 ms 的补力阶段仍立即关断四轮，含 tick 回绕。
- ARM 只编译对象，未链接：控制器 `.text` 5738 → 6418 B、`.bss` 288 → 300 B；私有状态增加 12 B。静态 `FrontSupport` 栈估计 152 → 160 B，`UpdateWithMode` 保持 96 B。这不是完整固件空间、栈峰值或实板时序证明。
- [verification.json](verification.json)记录 137 个生产/测试文件哈希及 .17 HEX 校验不变，警告为 0；[test_run.log](test_run.log)保存命令和输出。

## 复现与下一步

在仓库根目录、有本机 GCC 与现用 ARM 工具链的环境执行：

```powershell
python docs/stm32_evidence/2026-10-21-lf-first-start-prototype-v1/run_tests.py
```

构建输出仅在 `build/prototypes/lf_first_start_v1/`。也可单独执行同目录 `compare_recorded.py` 重算固定反馈比较。

下一步须经用户同意才合入生产、更新版本并完整链接候选固件。即使编译通过，也需要用户烧录后重新确认安全条件，先只读/架空，再决定是否进行一次带载测试；任何堵转或异常立即停止，不自动清故障重试。若仍不能正常起步，不据此直接放宽保护或继续叠加补力。
