# 0.18.16：RF 恢复与左转 RR 超调的离线复核

日期：2026-10-21，Asia/Singapore。用户授权继续分析。**本轮没有打开串口、转动车轮、改生产固件、编译新烧录文件、校准或烧录。** 编译的是桌面诊断程序，不是STM32候选固件。

## 判断

提高目标至0.30 rad/s确实改善了此前部分连续性，但[同固件实测](../2026-10-21-v01816-ground-pivot300/README.md)仍有RF间歇欠速、左转RR超调。存在值得处理的软件控制差异：**RF卸掉负载补偿后，在仍转动但明显欠速阶段不能直接恢复该补偿；接近静止后又允许负载项与短时恢复项同时上升。** 这一组合与记录中的“欠速—零计数—较快补力—恢复超调—撤补”过程吻合。

RR不是同一逻辑。左转窗口入口有额外FF和较大的正积分；额外FF随后正在退出，但正积分仅按普通KI逐步消退。不能把RR偏快解释成RF相同的前轮分支，更不能据此直接增加全车PWM。

这是控制分支诊断，不是已经确认了物理根因或证明某个新参数必然有效。机械/驱动/电源瞬态没有独立测量；本次不以静态11.4 V认定带载电源完全无问题，也不要求用户先更换硬件。

## 方法及复现边界

运行项目根目录下：

```powershell
python docs/stm32_evidence/2026-10-21-v01816-rf-rr-cycle-review/analyze.py
```

- `source_snapshot/`冻结交付0.18.16的5个C/头文件，逐一核对交付清单SHA256，生产C未修改。
- `cycle_replay.c`通过包含冻结C调用真实控制函数，只为诊断写入推断的窗口入口状态；输入是既有计数按现有LPF重建的反馈，不是模拟一辆车。
- `analyze.py`以`gcc -std=c11 -Wall -Wextra -Werror`编译桌面程序，未出现编译警告/错误；诊断程序不含串口/GPIO/RTOS操作。
- RF选择974582 ms作锚点：打印FF已降至基础FF、仍稳定同向转动，推断load=0、recovery=0、moving=40 ms，overspeed计时=0。在首帧反馈/积分打印小数格内搜索，150组中90组兼容；最优组后续122帧PWM均与记录相同，FF/P/I最大差各小于0.1‰。
- RR选择窗口首974482 ms，**外部bias由打印FF反推并作为输入给定**，没有重建后轮私有kick/steady/restart状态。70组中52组满足选定容差；最优127帧PWM均相同，FF/P最大差约0.0501/0.0988‰，I最大差约0.1194‰（略超单个0.1‰打印格），故不是逐位或全部打印格严格相等的证明。
- 兼容组只是本次测试的状态族，不是状态唯一性证明；尤其不能追溯RR窗口之前如何形成积分，也不能据回放预测修改算法后的真实轮速。
- 完整输入哈希、种子、误差和事件见`analysis.json`；逐帧推断值见`rf_compatibility_replay.csv`、`rr_compatibility_replay.csv`。CSV中的私有状态是推断值，不是新增板上遥测。

RF控制分支源码依据：

1. `WheelSpeedController_FrontSupport`中`coordinated`当前仅对LF为真。
2. RF在同向转动、欠速超过band时，只能把**已有积分超出10‰的部分**以有限速率转移到load；转移本身不增加FF+I。此前I很小甚至反向时，此路没有可转移量，负载项不能主动补回来。
3. 近静止连续确认60 ms后，RF允许load以200‰/s恢复，recovery另以250‰/s增加，20 ms内合计最多+9‰（还不含P等其他项）。这与上表FF每帧约+9‰一致。
4. 运动恢复后的短时项可以先转移到I；超速时短时项以400‰/s退出，持续超速满60 ms后load还可按200‰/s退出。该合成撤回过程比单项更快，记录中出现-12‰级FF下降。

974722～974982 ms连续14帧零计数，按帧计账280 ms。第一帧计数消失到第一次确认恢复补力974882 ms相隔160 ms；这包含滤波及确认过程，不是“额外固定160 ms延时参数”。不同采样/起始速度会改变此时间。不能为追求响应直接取消原始计数校验或把滤波一律移除。

LF已有的协调分支允许同向运动且确认欠速时有界恢复load，避免同次正积分重复增加，并对负载/短时项设置合成升降预算；RF目前保留旧分支。**下一步可设计RF限定候选复用这一思路，而不是再提高通用PWM上限。** 这不是说把LF代码直接套上就已完成实车验证。

## RR：补偿正在退，但积分记忆较大

左转RR目标打印+240 cps，基础FF约96.87‰。窗口入口974482 ms打印FF136.8‰，约有额外40‰；I45.5‰。974522 ms反馈548 cps，FF已降至128.8‰，I仍42.6‰，P约-46‰，实际命令仍约125‰。

974482～974682 ms，FF按每20 ms约-4‰降到96.8‰基础项，对应200‰/s退补；这与源码的后轮restart临时项衰减路径吻合，**不是本段没有撤补**。当时RR一直明显同向转动，现有源码也没有理由在这段重新触发近静止kick。

额外FF退完后，974682 ms I仍33.7‰，975282 ms约23.4‰，976082 ms约12.5‰，窗口末977002 ms约5.3‰。常规KI=0.25，20 ms单步积分变化约`0.005×误差cps`‰：超速100 cps时单步仅减约0.5‰，正常的缓慢消退足以保留一段历史支撑。P阻尼确实在减输出，没有发现符号反了或未执行纠偏的证据。

窗口不覆盖前面全部起步，不能宣称这45.5‰积分一定由某次特定启动/重启形成；RR回放给定外部bias，更不能用它证明后轮私有状态已重建。若后续仍需优化RR，应针对“超速时历史正支撑的有界退出”独立设计与验证，避免同时改RF和RR而失去归因。

## 建议的下一版范围（计划，尚未实施）

优先仅处理RF的原地转向补偿协调：

- 同向确认运动但明显欠速时，允许有界恢复已有load上限内的补偿，不能等到轮子接近停止才补；同帧避免叠加正积分。
- load与短时恢复项共享升降预算，恢复后可撤、超速时可退，不抬高峰值权限。
- 保留RF原有方向相关load上限60/45‰、积分50‰、PWM300‰、目标速度语义、失速故障锁存及STOP/断链/急停。
- LF与两后轮暂不改，直行/滚动转向、编码器、USB、IMU、几何及CubeMX不改。
- 先用桌面隔离回归确认除RF/PIVOT外逐位不变，验证限幅、模式切换、符号切换、恢复失败及停车；构建后再另请用户烧录。实车仍要架空后再落地，不能把固定反馈回放当实车改善证明。

此报告没有生成0.18.17，没有批准/执行新的运动。用户若更重视尽快交接，可保留当前0.30 rad/s人工试验档位和已知局限，不强制追求单帧零误差；但不能把尚存RF停顿和RR超速写成“ROS使用无误差”。
