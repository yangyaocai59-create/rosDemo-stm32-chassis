## 反馈间歇仍在

运动满1秒后，按20Hz USB累计值查找相同净计数的至少100ms平台，发现LF两次（240/200ms）、LR两次（100/340ms）、RF三次（200/260/240ms）、RR一次（100ms）。时间是已记录相同值的首末源时间戳跨度，不等于实际轮子停止时长；USB离散采样可能漏掉区间内正反抵消，需结合原始trace/视频。详细区间见`analysis.json`，不能只看平均速度或完成角度。

本次128帧内部环抓到了LR较长平台：

- 同期用户整体观察“基本连续”。尚不能确定是短暂真实近停、带电反馈问题还是现场观察分辨率不足；**PWM非零不证明车轮一定在转，stall标签也不证明车轮物理停住。** 保留两种证据，不盲目加PWM或宣布编码器正确。
- 其他三轮尾段127帧没有零增量；这只覆盖最后约2.54秒，不代表整段约20秒都没有间歇。环外没有详细PWM/FF/P/I记录，不能用尾段数据替代全程。

- `capture/`：原始本轮UART、USB payload、解码和命令/清故障ACK/停车状态摘要。
- `pivot_180_repeat_once.py`：本次脚本原样副本，**会清一次故障并控制车辆，不可擅自重新执行**。运动前自测通过积分、重复时间戳、间隔及回绕检查和语法编译。本次异常分支支持在同一串口连接、已停车后导出环；本次走正常停车导出。
- `analyze_capture.py`：不导入串口、不控制硬件的离线分析，生成`analysis.json`、`trace_parsed.json`、`wheel_motion.csv`。
