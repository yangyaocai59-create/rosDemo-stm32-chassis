- 输入为[本次落地证据](../2026-10-21-v01815-ground-pivot/README.md)末段127帧；目标、原始计数/轮速、FF/P/I、PWM均来自已采集日志，没有新采样。

- 根据20 ms实际样本周期和50 ms一阶滤波重建小数轮速；使用与固件相同的 float 机械参数和运算次序计算目标约160.43 cps（trace整数打印为160；精确值以 C 程序为准）。首次打印轮速/FF/I 的截断区间内做网格拟合。
- 假定窗口起点 transient=0、moving_ms=40；load、I、轮速小数属于拟合。还可能有其他未测试的初态族，不能把它们当板上直接上报的私有字段。
- LF 测试1100组初态，605组在本判据内兼容；兼容组 recovering/overspeed计时序列相同。选中初态 load约46.4825‰、I约10.175‰、轮速151.76 cps。
- LF 126/127帧PWM完全吻合，1帧差1‰；FF/P/I相对截断打印值最大差约0.092/0.100/0.100‰。不是“全帧精确回放”。

- 只是把**原记录反馈**输入真实原C算法，没有摩擦/电流/轮胎/机械/电源瞬态模型，也没有改变算法后的闭环反馈预测。

### 滤波与量化

部分撤减帧原始速度已为150 cps，滤波仍为约183～203 cps，存在正常滤波延迟；但也有原始200～350 cps与滤波同时超速的帧，因此不能说超速全是滤波虚假产生。低速20 ms计数的50 cps量化也会造成波动，不宜直接去掉滤波或反转编码器符号。

本段最长连续零计数180 ms，尚未到200 ms强制置零时间；.15重放本段不依赖该强制置零。滤波近零最长160 ms，也没到1500 ms保护期限。无故障符合当前保护设计，不应为了“看到故障”缩短安全门槛。

原记录req/applied/target恒定，127个ACTIVE帧STBY=1、PWM未归零、无超期/通信错误；未见上位机松键、断链停车或任务周期异常导致这段循环的证据。20 ms快照不是示波器，不能排除未采到的驱动/电源瞬态或编码器硬件问题。

## 建议设计范围（未执行，待用户决定）

建议下一版先做离线原型，重点是**负载支撑变化协调**，不是提高目标速度、PWM/I上限或加长一次冲力：

1. 临时补力保持快速可撤回；持续负载基线采用更慢、可逆的调整。保留真正持续超速可撤回，不引入永不撤销的支撑底座。
2. 对负载/临时项合成变化做统一预算与顺序协调，避免两项同时大幅抬升或撤减；只合并撤减预算不足以修复第一次“无临时项”的负载撤减事件。
3. 已确认运动、随后明显欠速时，在原额度内平滑恢复合适支撑，不必一直等到近零才修复负载估计；必须防止和普通I重复加力/积分累积，不能把“恢复负载”当新增固定前馈。
4. 优先限定LF做原型，不把新规则直接套给已改善的RF；RF及后轮保留.15并作对照。保留成功的欠速交接、原峰值/积分预算、普通运动策略、所有故障关断。编码器/滤波/USB/IMU暂不动，避免把归因混在一起。
5. 离线先覆盖首次负载撤减、再次有临时项的撤减、运动中恢复、真实持续超速、持续堵转、模式/符号切换与八条安全路径。参数尚未定，不从这一段规定反馈宣称物理稳定；通过后才准备候选，实车仍需单独安全确认。
