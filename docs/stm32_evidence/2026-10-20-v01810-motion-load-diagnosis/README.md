# 0.18.10 同固件直行与原地转向负载对照

日期：2026-10-20（Asia/Tokyo）。结果：用户反馈本组现场表现“都正常”；直行轮速跟踪连续，原地转向的前轮支撑需求显著增大，LF 仍大量触及积分上限。证据支持优先检查 pivot 工况下的负载支撑/前馈，而不是先修改通用编码器或 USB 配置；不能证明硬件、电流限制或机械差异已全部排除，也不能标记整车通过。

## 目的、条件与范围

- 保持已烧录的 `0.18.10-rear-transient-assist`，本轮没有修改生产固件、编译、烧录、复位或推送仓库。
- 用户明确确认前后各约 80 cm 空间、线缆有余量、车辆落地且无人接触，同意这组对照。
- 顺序：前进 +37 mm/s 6 秒、后退 -37 mm/s 6 秒；然后左/右原地转向 ±350 mrad/s 各 6 秒。每段 20 Hz、120 条速度指令，STOP 并读完内部 trace 才继续下一段。
- 直行命令距离约 22 cm，不是独立测量到的车体位移。固件中直行轮速目标为 ±282 cps，pivot350 为 ±280 cps，幅值相差约 0.7%，可以在同一轮、同转动方向下对照。
- USB COM4、CH340 COM8。CH340 open 前 DTR=False、RTS=False，整个采集期间保持连接。
- 固件身份依据用户烧录报告及此前匹配控制行为；本轮未回读 Flash 或重新捕获 Boot Banner。
- 地面、位置、轮胎接触与重心未做实验室受控复现；控制状态也因模式和历史不同而不同。这是机械运动工况诊断，不是两个固件版本 A/B，也不是电流/力矩模型的标定。

## 350 与此前 200 mrad/s：仍有低速控制问题

两组都是 0.18.10，轮速目标分别约 ±280 和 ±160 cps，不是固件升级对照。

本次 pivot350 末段：

- 左：LF/LR/RF/RR 最长连续零计数约 180/0/140/180 ms，四轮均值较接近目标，但 LF/RF 滤波峰值约 489/509 cps，波动仍大。
- 右：四轮均没有零计数帧，但 LF 平均欠速、RF 平均超速，不能仅以“没有停顿”判定通过。
- 对比此前 pivot200，左 LF/LR 的长零计数减少，但目标速度和机械状态都不同，不能视为较高目标已经解决低速需求。

新旧目标的原始指标见 `target200_vs350_comparison.json`；其中 baseline/candidate 仅是工具字段，分别表示 200/350 目标，不表示两个固件版本或最终验收。

## 判断及下一步建议

1. 当前同轮同方向的直行能够连续跟踪、协议与采样时序正常，不支持优先将症状归咎于通用 USB 指令断续或编码器配置。不能据此完全排除仅在大负载出现的硬件/电流/机械问题。
2. 异常主要集中在 pivot 工况的额外阻力、前后轮差异，以及固定积分上限/启动残余支撑承担长期负载的方式。仅继续改变后轮启动延时已不够。
3. 下一版如调整，应把 pivot 的稳态负载前馈显式独立出来，并按轮子/方向核对；保持直行前馈和增益不动、保留 0.18.10 后轮短时补力分离。
4. 新稳态前馈必须与启动补偿一起核算，避免在新增支撑上又完整叠加旧 kick。不要简单扩大总 PWM/积分上限，也不要用 ROS 轮距、IMU 或协议修改掩盖轮速跟踪误差。
5. 参数只能作为候选，先离线验证边界，再用相同 200/350 目标和直行对照验证；如改善不稳定，应检查负载分布、轮胎/地面接触、安装及供电能力，而不是无限堆叠补偿。

本次没有实施下一版修改。

## 停车与通信

- 每段 120 条、四段合计新增 480 条速度命令，全部接受，新增拒绝 0。运行前固件已累计接受 240 条，结束累计为 720，不能把历史累计当成本次命令数。
- 两个采集进程主机 CRC=0，固件 CRC/RX overflow/TX drop=0，fault=0/0。
- 日志 motor_dt=20..20 ms、safety_dt=10..10 ms、overrun=0/0、log_drop=0。
- 四次 STOP 均确认 IDLE/EXPLICIT、请求速度和四轮速度 0。
- 最终源时间 656753 ms、flags=0x0150、四轮速度 0，车辆已停车。
- 没有重做物理拔线、急停或掉电。IMU 仍未校准，本轮没有用 IMU 验收车体角度；交 ROS 前仍需显式校准保存。
